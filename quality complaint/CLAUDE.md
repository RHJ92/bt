# quality complaint — 가맹점 품질 클레임 관리

가맹점 품질 클레임 접수 → 점주 안내문 작성 → 노션 QC DB 기록까지의 작업 거점.

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `claims/` | 건별 작업 MD (`YYMMDD_품목_매장.md`) — 경위, 최종 발송본, 후속 조치 추적 |
| `captures/` | 카톡 캡처 등 원본 증빙 (건별 하위 폴더 `YYMMDD_품목_매장/`) |
| `reference/` | 수입사 회신, 전산 캡처 등 근거자료 |

## 노션 연동

- QC 허브 페이지: https://app.notion.com/p/3a50bbc5ac2680aa9160f277ea616507
- QC 데이터베이스 data_source_id: `3a50bbc5-ac26-8035-8130-000bd910d55b`
- 건당 노션 페이지 1개(제목: `YYMMDD 품목 이슈 — 매장 답변`). **노션이 최종본 원본**, 로컬 MD는 작업·기록용
- 노션 페이지 구성: 클레임 개요 / 로트 추적 / 발송용 안내문 / 작성 원칙(내부 메모) / 발송 전 확인 필요 / 수입사 답변 요약 — 큰 헤딩 금지, 굵기로만 구분

## 워크플로

1. 캡처를 `captures/건별폴더/`에 수령 → 점주 감정 상태·핵심 불만 파악
2. 수입사 회신·전산(로트/이력번호 추적) 취합
3. 안내문 초안 작성 → 노션 QC DB에 페이지 생성
4. 구매팀장·운영팀장 검토 → **지키지 못할 약속 배제** 기준으로 확정
5. 발송 후 `claims/` MD에 최종 발송본 + 후속 조치 기록, 노션 반영

## 안내문 작성 원칙 (260722 아롱사태 건에서 확립)

- **사과는 짧게 1회**, 나머지는 전부 "본사가 하는 행동"으로만 구성 — 길어지면 변명으로 읽힘
- **지키지 못할 약속 배제** (팀장 검토 기준): 실행 계획이 확정되지 않은 검증·방문·클레임 제기·중간 안내 약속은 문서에 넣지 않는다
- **반품 약속 금지** — 문서에 남으면 선례가 되어 유사 상황마다 반품 요구 반복. "확인 후 처리 방안 안내"로 표현해 사안별 대응 여지 확보
- **점주 주장 반박 금지** — 반박 대신 검증 약속으로 전환 ("그냥 넘기지 않겠습니다"). 수입사 논리는 인용 형태("수입사로부터 답변받았습니다")로만 전달
- **의도적으로 뺄 것**: 타 매장 클레임 없음("너만 예민하다"로 읽힘) / 수급 감소·단가 상승(가격 인상 예고로 읽힘)
- **절차 요구 최소화**: "사진 몇 장 + 체감 비중 %" 수준까지만. 분류·계량 요구는 반발 유발
- 점주가 불리한 사실(문제 로트 마지막 물량 수령 등)은 "점주님 제보로 특정·조치"로 프레이밍 — 손해 봤다는 느낌 방지
