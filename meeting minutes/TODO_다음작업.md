## 🔴 1순위-B — 쓰기 토큰 재발급 (콘솔 작업 불필요)

**2026-07-29 콘솔 확인 결과: 앱은 이미 "프로덕션 단계" / 사용자 유형 "외부"**
→ 처음에 "테스트 상태라서 7일 만료"라고 진단했던 건 **오진**. 콘솔에서 할 일 없음.

**실제 원인**: 백업 파일 `credentials.json.bak-20260720-171310` 안에 **`refresh_token_expires_in`** 필드가 있음.
Google은 이 필드를 **refresh token에 수명이 있을 때만** 내려줌 → **07-20 시점엔 앱이 아직 테스트 상태**였다는 뜻.
그때 발급된 쓰기 토큰이 7일 뒤(07-27경) 만료 → 07-29에 사용하려다 `invalid_grant` 발생.

지금은 프로덕션이므로 **새로 발급받는 토큰은 만료되지 않음.**

### 할 일 — 명령어 한 줄
```
python C:\Users\BLUETREND\.gdrive-mcp\reauth_rw.py
```
- 브라우저 열리면 **드라이브 소유 계정**으로 로그인
- "확인되지 않은 앱" 경고 → **[고급] → [(안전하지 않음) 계속]**
- 기존 파일은 자동 백업됨
- 스크립트가 끝에 만료 여부를 판정해 알려줌:
  - `만료 없는 refresh token으로 발급됨 (정상)` → 끝. 이후 재인증 불필요
  - `[경고] refresh_token_expires_in 필드가 있습니다` → **7일 뒤 또 만료됨**.
    이 경우 아래 서비스 계정 방식으로 전환해야 함 (외부+미확인 앱 + restricted 스코프 조합 이슈)

### 검증된 사실 (재진단 과정에서 확인)
- `credentials_rw.json`의 client_id·secret은 현재 클라이언트와 **일치** → 클라이언트 불일치 문제 아님
- `expiry: 2026-07-20T05:52:39Z`는 access token 만료 시각이라 정상 (마지막 갱신이 07-20)
- 읽기 토큰(`credentials.json`)은 아직 살아 있으나 같은 이유로 언제든 죽을 수 있음

### 방법 2 — 서비스 계정 (위 경고가 뜨거나, OpenClaw 자동화 붙일 때)
refresh token 개념 자체가 없음 → **영구 무만료, 브라우저 인증 영원히 불필요**
1. GCP 콘솔 → **IAM 및 관리자 → 서비스 계정 → [서비스 계정 만들기]**
2. 계정 **이메일 복사** (`...@claude-drive-503003.iam.gserviceaccount.com`)
3. 해당 계정 → **키 탭 → 키 추가 → 새 키 만들기 → JSON** → `.gdrive-mcp\service-account.json`으로 저장
4. 드라이브에서 **회의 폴더 우클릭 → 공유** → 위 이메일을 **편집자**로 추가

※ 서비스 계정은 별도 신원이라 **공유해준 폴더만** 접근 가능(오히려 안전)

### 곁들여 정리
현재 읽기(`credentials.json`)/쓰기(`credentials_rw.json`) 2개로 나눠 씀 → **만료 위험 2배**.
같은 계정·같은 클라이언트이므로 `drive` 스코프 하나로 합쳐 파일 1개만 쓰는 게 관리 쉬움.
