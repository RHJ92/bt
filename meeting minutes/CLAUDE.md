# meeting minutes — 회의록 정리 작업 거점

클로바노트 STT(구글 드라이브) 회의 녹취를 읽어, 노션 **「회의 정리」 DB**에 완성도 높은 회의록 페이지로 정리하는 작업 공간. 이 파일만 읽으면 세팅·판단 기준·형식을 전부 알 수 있게 정리해둠.

> 사용자 요청 한마디: **"드라이브 회의록 중 노션에 없는 것 정리해줘"** → 아래 워크플로우대로 진행.

---

## 연결 (이미 세팅됨)

| 대상 | 접근 방법 |
|---|---|
| **노션** | MCP(`notion`) 연결됨. 반드시 **gmail 계정 `yy1005.rhj@gmail.com` / "호정 류님의 워크스페이스"**. (회사 `bt1005@bluetrend.co.kr`은 빈 워크스페이스라 404 — 잘못 붙으면 재인증) |
| **구글 드라이브** | 사용자 GCP OAuth. 자격증명은 저장소 밖 `C:\Users\BLUETREND\.gdrive-mcp\` 에 보관(깃 커밋 금지) |
| **claude CLI** | PATH에 없음. 번들 실행파일 사용: `C:\Users\BLUETREND\.vscode\extensions\anthropic.claude-code-<버전>-win32-x64\resources\native-binary\claude.exe` |

**드라이브 자격증명 파일** (`.gdrive-mcp\`)
- `gcp-oauth.keys.json` — OAuth 클라이언트(데스크톱)
- `credentials.json` — 읽기 전용(`drive.readonly`) 토큰 (MCP `gdrive`가 사용)
- `credentials_rw.json` — 읽기+쓰기(`drive`) 토큰 (파일 이동/수정용, 파이썬으로 직접 호출)

**드라이브 실무 팁**
- .docx는 구글 export 불가 → `files().get_media`로 내려받아 `python-docx`로 텍스트 추출
- 터미널이 한글 파일명을 깨면 결과를 UTF-8 파일로 써서 확인
- 파일 이동 = `files().update(fileId, addParents=대상, removeParents=현재부모)`
- pip: google-api-python-client, google-auth, google-auth-oauthlib, python-docx

## 입출력

**입력** — 구글 드라이브 회의 폴더 (ID `1MIEikr3-AHBr_wu99ikhGSboqVJ_YBqQ`)
- 폴더 **루트에 남아 있는 파일** = 아직 노션에 안 올라간 회의록 (= 처리 대상)
- 처리 끝난 파일은 하위 폴더 **`노션 업로드 완료`** (ID `1RUD0rVy5vToUPKgoW56q3qaKEnutbJDL`) 로 이동
- 파일명 규칙: `YYMMDD` 또는 `M_DD` (예: 2673캐틀팜 = 07-03, 2676 = 07-06)

**출력** — 노션 「회의 정리」 DB
- data source: `collection://6e1e9aa5-e125-4287-8f6a-9bb900adaa03`
- 회의록 1건 = 페이지 1개
- ※ 작업 기준은 이 파일이 원본. (구 노션 가이드 페이지는 이 파일로 이관 후 삭제됨)

## 워크플로우

1. 드라이브 회의 폴더 루트 스캔 → 노션 「회의 정리」 DB와 대조해 **누락분** 식별
2. 대상 파일(.docx) 다운로드·텍스트 추출 → §STT 교정 적용
3. 아래 **본문 형식**으로 구조화 (맥락 명확한 내용만, 억지 추정 금지)
4. 노션 「회의 정리」 DB에 페이지 생성
5. 원본 파일을 드라이브 `노션 업로드 완료` 폴더로 이동
6. STT 불확실·추정 항목은 정리 끝에 "확인 부탁"으로 사용자에게 보고

## 노션 페이지 속성

| 속성 | 타입 | 값 규칙 |
|---|---|---|
| 회의명 | title | 날짜 빼고 핵심 주제. 예: `주간 구매보고 — A·B·C·D` |
| 날짜 | date | 회의일 YYYY-MM-DD, is_datetime=0 |
| 구분 | select | `내부미팅` / `외부미팅` (대표 참석=내부) |
| 관련 프로젝트 | select | `영영상점` / `옥된장` / `기타` (주간 구매보고는 보통 옥된장) |
| 참석자 | text | **팀 단위 표기, 개인 이름 금지.** 예: `대표, 구매팀, 운영팀` |
| 결정사항 있음 | checkbox | 결정 있으면 체크 |
| 액션아이템 있음 | checkbox | 액션 있으면 체크 |

## 본문 형식 (2026-07-20 신규 버전)

기준 샘플: 노션 「회의 정리」의 **"…(샘플)"** 페이지. 이 순서 고정, 제목 계층은 **볼드 텍스트**만(`#`·`##` 금지).

```
⏱ 3줄 요약 (바쁘면 여기만)
- 핵심 결정·결론 3줄. 이것만 읽어도 결론이 잡히게

회의 흐름 (논의 순서 그대로)
1. (타임스탬프 범위) 단계 요약 — 핵심 쟁점은 비중까지 표시(예: "회의의 2/3")

안건별 상세
① 안건명 (성격 태그: 신규 검토/긴급/확인 필요/보고/★ 핵심 쟁점)
- 배경: 왜 나온 얘기인지
- 논의: 오간 의견. 입장 갈리면 양쪽 논리를 나란히 (수치·기한은 볼드)
- 결론: 정리된 방향. 미결이면 "무엇을 확인해야 결정되는지"

✅ 액션 아이템 — 표로 (담당 | 할 일 | 기한 | 후속 확인)
- 담당은 팀명(구매팀/운영팀/개발팀), 개인 이름 금지
- 후속 확인 = 결과가 누구에게 다시 보고되는지

📌 다음 일정 / 미결
- 이어지는 회의·마감, 아직 결정 안 된 것과 판단 시점
```

**어투:** 깔끔한 문어체, 중립, 명사형/단문 종결(~함, ~예정, ~필요). 구어체·감탄 금지.

## 정리 원칙

1. **억지 추정 금지.** STT가 엉킨 구간은 맥락상 분명한 것만 기재.
2. 확신 없는 수치·고유명사는 원문 값 유지 후 "확인 부탁"으로 보고.
3. 결정란에는 **확정 사항만**. 검토·고려·제안은 안건별 상세의 논의에만.
4. 발화자↔이름 매칭은 회의마다 다름 — 가이드 기본값(발화자2=대표) 맹신 말고 문맥으로 판단.
