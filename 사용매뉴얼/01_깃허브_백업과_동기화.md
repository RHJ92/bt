# 깃허브 백업과 동기화

## 푸시와 풀, 방향이 반대다

| 용어 | 방향 | 언제 |
|---|---|---|
| 푸시 (올리기) | 내 PC → 깃허브 | 내가 뭔가 바꿨을 때 |
| 풀 (받기) | 깃허브 → 내 PC | 다른 PC에서 바꾼 걸 가져올 때 |

## 두 마디 습관

- 작업 시작할 때: Claude에게 **"최신으로 받아줘"** (= git pull)
- 작업 끝날 때: Claude에게 **"깃허브에 백업해줘"** (= 커밋 + 푸시)

시작할 때 받는 걸 잊으면 두 PC 내용이 충돌할 수 있다. 잊었어도 Claude가 풀어줄 수 있음.

## Q. 한 세션에서 백업하면 다른 세션에서 바꾼 것도 올라가나?

올라간다. 푸시는 세션 단위가 아니라 **폴더(저장소) 단위**다. rhj 폴더 아래 모든 변경(edit, Data, agent_livestock_products 전부)이 마지막 백업 이후 기준으로 한꺼번에 올라간다. 하루 끝에 아무 세션에서나 한 번만 백업하면 됨. 단, rhj 폴더 밖(바탕화면, 노션, Claude 메모리)은 이 백업과 무관.

## Q. 푸시했는데 "변경 사항 없음"이라고 나온다?

정상이다. 이미 다 올라갔다는 뜻. git은 변경이 없으면 빈 커밋을 만들지 않는다.

- 소스 제어 패널의 "변경 내용"에 파일이 보이면 → 올릴 게 있음
- 비어있으면 → 이미 동기화 완료
- 확실히 알고 싶으면 Claude에게 "백업 상태 확인해줘"

## Q. 폴더명을 바꾸면 푸시에 자동 반영되나?

된다. 깃허브 연결 정보는 폴더 안 .git에 있어서 폴더명·위치를 바꿔도 연결은 따라간다. 소스 제어에는 "옛 이름 삭제(D) + 새 이름 추가(U)"로 보이는데 커밋하면 "이름 변경(R)"으로 합쳐진다.
주의: 그 폴더명을 적어둔 문서(CLAUDE.md 등)는 자동으로 안 고쳐지므로, 이름 바꾸면 Claude에게 알려서 참조까지 정리할 것.

## VS Code 소스 제어 패널로 수동 푸시하는 법

1. 왼쪽 소스 제어 아이콘 (가지 모양, 숫자 배지 = 변경 파일 수)
2. 메시지 입력 (뭘 바꿨는지 메모) → ✓ 커밋
3. 커밋 후 나타나는 "변경 내용 동기화" 버튼 클릭 (= 푸시)

완전 자동 푸시는 권장하지 않음 — 실수까지 즉시 올라간다. 하루 한 번 리듬이 적당.
