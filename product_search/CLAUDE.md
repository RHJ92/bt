# product_search — 규격 상품 온라인 탐색 거점

원하는 **규격(치수·용량·재질·입수 등)을 주면 온라인 쇼핑몰에서 그 규격에 맞는 상품을 찾아** 후보를 비교표로 정리하는 작업 공간.
매입처에 견적을 받아 비교하는 일은 `bidding/`에서 다루고, 여기는 **공개 쇼핑몰에 이미 올라와 있는 기성품을 찾는 일**이 대상이다. 찾은 후보가 정식 거래 검토로 넘어가면 그때 `bidding/`에 업체 폴더를 만든다.

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `requests/` | 건별 탐색 기록. 파일명 `YYMMDD_품목명.md` (예: `261012_158파이_탕용기.md`). 양식은 `requests/_요청_양식.md` |
| `output/` | 보고·공유용으로 엑셀이 필요할 때만 작성. 파일명 `YYMMDD_품목명_후보비교.xlsx` |
| `reference/` | 반복해서 쓰는 자료 — 자주 찾는 규격 표기법, 쓸 만했던 판매처 목록 등 (쌓이면 만든다) |

## 작업 순서

**1. 규격 접수 — 조건을 필수/허용/무관으로 나눈다**

찾기 전에 아래를 채운다. 빠진 항목은 한 번에 모아서 묻되, 물어보는 동안에도 확정된 조건만으로 탐색을 시작한다.

| 항목 | 확인할 것 |
|---|---|
| 용도 | 어디에 쓰는지 (매장 포장용·사무용·샘플 등) — 대체품 판단의 기준이 된다 |
| 필수 규격 | 반드시 맞아야 하는 값. 치수는 단위(mm·cm·파이)와 측정 위치(외경/내경, 상단/하단)까지 |
| 허용 오차 | ±몇 mm, 용량 ±몇 ml까지 되는지. 안 주면 "정확히 일치"로 본다 |
| 재질·색상·인쇄 | PP/PET/펄프, 무지/인쇄, 내열 여부 등 |
| 수량 | 필요 수량과 구매 단위(낱개/박스) — 단가 구간과 MOQ 판단에 필요 |
| 예산·기준 단가 | 현재 쓰는 상품의 단가가 있으면 그게 비교 기준 |
| 납기 | 언제까지 받아야 하는지 |
| 제외 조건 | 피할 판매처·원산지·브랜드 |

**2. 탐색**

- 검색어는 한 가지로 끝내지 않는다. 같은 규격도 판매자마다 표기가 다르다 (예: `158파이` = `158mm` = `Ø158` = `16cm`, `탕용기` = `국용기` = `찜용기`). 표기 변형을 3개 이상 돌린다
- 종합몰(네이버쇼핑·쿠팡)로 시세와 표기 관행을 먼저 잡고, 품목 전문몰(포장재·주방용품·사무용품 도매몰)로 들어간다
- 로그인해야 가격이 보이는 몰, 옵션을 눌러야 규격이 나오는 상품은 크롬 확장(`mcp__claude-in-chrome__*`)으로 직접 열어서 본다. 단순 검색은 WebSearch·WebFetch로 충분
- **검색 결과 목록의 제목만 보고 후보에 넣지 않는다.** 상세페이지까지 들어가 규격표를 확인한 것만 후보다

**3. 규격 검증 — 상품별로 판정을 붙인다**

| 판정 | 기준 |
|---|---|
| 일치 | 필수 규격이 상세페이지 수치로 전부 확인됨 |
| 허용범위 | 허용 오차 안에서 다름 — 어느 값이 얼마나 다른지 적는다 |
| 확인필요 | 상세페이지에 수치가 없거나 이미지로만 있어 판독이 불확실함 — 판매자 문의 사항으로 넘긴다 |
| 불일치 | 필수 규격이 다름 — 후보에서 뺀다. 단, 왜 뺐는지는 기록에 한 줄 남긴다 (같은 상품을 다시 보지 않기 위함) |

자주 틀리는 지점:
- 외경과 내경, 상단 지름과 하단 지름을 섞어 적는 판매자가 많다. 어느 쪽인지 명시가 없으면 **확인필요**
- 용량은 "가득 채운 용량"과 "실사용 용량"이 다르다
- 뚜껑·받침이 별매인지 세트인지
- 상품명의 규격과 옵션 선택 후 규격이 다른 경우 — 옵션 기준으로 적는다

**4. 단가 환산 — 같은 잣대로 맞춘다**

- **개당 단가 = (상품가 + 배송비) ÷ 입수.** 필요 수량을 사는 경우의 실제 결제 기준으로 계산
- VAT 포함/별도를 통일한다. 쇼핑몰 표시가는 대개 포함, 도매몰·견적은 별도 — 비교표는 **VAT 별도**로 맞추고 원래 표시가를 옆에 남긴다
- 수량 구간 할인, 묶음배송 조건, 도서산간·제주 추가비가 있으면 적는다
- 쿠폰·회원 등급 할인가는 기준에서 뺀다 (재현이 안 됨). 참고로만 표기
- 기준 단가(현재 쓰는 상품)가 있으면 차액과 증감률을 같이 낸다

**5. 정리·보고**

채팅 답변은 비교표 하나 + 추천 1줄. 표 열은 아래 순서로 고정한다.

| 판매처 | 상품명 | 규격(확인값) | 판정 | 입수 | 상품가 | 배송비 | 개당 단가(VAT 별도) | MOQ·납기 | 링크 |
|---|---|---|---|---|---|---|---|---|---|

- 링크는 검색 결과 주소가 아니라 **상품 상세페이지 주소**
- 후보는 3~5개로 추린다. 많이 나열하는 것보다 왜 이 순서인지가 중요
- 조건에 맞는 상품이 없으면 없다고 쓴다. 가장 가까운 대체품과 **어느 조건을 풀면 선택지가 생기는지**를 같이 제시
- 건별 기록은 `requests/`에 저장 — 조회일을 반드시 적는다 (가격·재고는 그날 값)

## 원칙

- **조회만 한다. 장바구니 담기·주문·결제·회원가입·판매자 문의 등록은 사용자가 명시적으로 시킬 때만.**
- 가격·재고·배송비는 조회 시점 값이다. 기록과 답변에 조회일을 붙이고, 며칠 지난 기록을 다시 쓸 때는 재조회한다
- 상세페이지에서 확인하지 못한 값을 추정으로 채우지 않는다. 빈칸은 `확인필요`로 두고 판매자 문의 문안을 붙인다
- 식품 접촉 용기·포장재는 재질과 식품용 표시 여부를 같이 본다
- 판매자 신뢰도(사업자 정보·리뷰 수·최근 리뷰 일자)는 판정과 별개로 비고에 적는다. 최저가가 리뷰 0건 판매자면 그 사실을 표에서 숨기지 않는다
- 엑셀을 만들 때 글꼴은 루트 `_공용/폰트크기_작업기준.md`를 따른다

## 누적 루틴

건이 끝나면:
- 새로 알게 된 규격 표기 변형·검색어 → `reference/검색어_표기사전.md`에 추가
- 규격표가 충실하고 응대가 좋았던 판매처, 피해야 할 판매처 → `reference/판매처_메모.md`에 추가
- 같은 절차가 서너 건 반복되어 굳으면 `.claude/skills/`에 스킬로 옮긴다
