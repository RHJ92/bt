# price_change — 제때 품목 요청 (단가 변경 · 신규 코드 생성)

> 2026-11-05: 루트 `제때코드관리/`를 `code_requests/`로 합침 — 신규 전용상품 코드 생성 요청서(기존 요청서 복사 → 행 교체). 진행 현황은 `code_requests/_지금상태.md`

가맹점 공급가가 바뀔 때 제때(물류사)에 코드 단가 변경을 요청하는 루틴. 공급가가 정해지면 정해진 율로 제때 매입가(jt 매입가)가 따라 정해지고, 그 값을 제때 코드에 반영해 달라고 메일로 요청한다.

## 절차

1. **변동 확인** — 대상 품목·변경 공급가·적용일 확정. 축산품은 `중간단가변경이력`의 최신 변경일자 행을 읽고, 가맹점 안내문(노션 「안내문 초안 작성」 DB)과 품목·단가·적용일을 대조
2. **코드 전개** — 원물 하나가 바뀌면 `축산원물마스터` 매핑표의 관련 제때코드 **전체**를 대상으로 함 (예: 우삼겹슬라이스 → C·S·M 3코드)
3. **환산** (아래 규칙) + **기존가 조회** — 기존 3종 단가는 `신_단가변동사항`에서 같은 코드의 가장 최근 "변경" 값. `신_품목리스트`는 대조용
4. **입력대기 탭 작성** — 통합 재고 시트 `LS_신_단가변동사항_입력대기` 탭에 `신_단가변동사항`과 같은 열 순서(A~O)로 작성. 이전 건은 지우고 새로 씀
5. **사용자 복붙** — DAILY `신_단가변동사항`의 다음 빈 행에 값만 붙여넣기(Ctrl+Shift+V): B(요청일) / D(제품코드) / H~M(단가 6개) / O(특이사항). A·C·E·F·G·N열은 기존 수식이 채움
6. **요청 엑셀** — `requests/`의 직전 파일을 복사해 행 교체 (bt 매입가 열 없음)
7. **메일** — ECOUNT 웹메일(크롬) 보낸 메일함에서 직전 "단가 변경 요청 건" 메일을 열어 **재전송** → 수신인 그대로, 제목과 본문 표만 수정. 본문은 인사말 + 표(첨부 없이 본문에 표). **발송은 사용자 확인 후**

## 규칙

- **신_단가변동사항에는 공급가(판매가) 변경 건만 입력.** bt 매입가만 바뀐 건은 넣지 않음 (축산품 bt 매입가는 통합 재고 시트 LS_ 탭에서 별도 관리)
- **변경 판매가** = kg당 공급가 × 박스당 kg (BOX 10kg 품목 ×10 / 스지 ×4.1 / 계근(KG) 품목 ×1)
- **변경 jt 매입가** = 변경 판매가 × (1 − `신_품목리스트` 정보공개서 마진율). 축산품 10% → ×0.9, 곰피 15% → ×0.85
- **변경 bt 매입가** = kg당 구매가 × 같은 중량 (시트 기록용, 요청 엑셀·메일에는 안 들어감)
- 요청일 칸 = **적용일**
- 메일 제목: `{브랜드} 단가 변경 요청 건_{품목,품목}` / 받는사람 (제때)이정택 프로, 참조 5명 — 재전송으로 유지
- 재고 구간(A/B/C)이 나뉜 품목은 공급가가 바뀌는 구간의 단가를 쓰고, 적용일은 안내문 기준

## 알아둘 것

- 철산장 `CC314554 (계근)어롱사태`는 옥된장과 집계가 겹치지 않게 일부러 "어롱"으로 표기한 코드. 재고 소진 후 중단 예정 → 아롱사태 변경 때 포함하지 않음
- 소꼬리는 당분간 S(CC310896)만 운영 — M·Y는 품목리스트 단가가 예전 값이어도 그대로 둠
- DAILY `신_단가변동사항` N열(인상·하율)은 101행부터 수식 분모가 J77로 고정돼 있어 값이 틀리게 나옴. 수식은 건드리지 않기로 함 — 정확한 율은 입력대기 탭·요청 엑셀 기준
