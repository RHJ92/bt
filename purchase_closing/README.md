# purchase_closing — 제때 매입마감 검토

구글시트 「DAILY 업무 진행_발주,단가,코드」(ID `1x1KueQVbAyKYQJV_3pkcHZhJc5YJqjSbadiCIr3tRns`)의 발주진행현황·매입사마감을 제때 정산과 대조하고, 팀장 검토 전후로 무엇이 바뀌었는지 추적하는 거점.

**구조**
- `sheet_snapshot.py` — 시트 탭 스냅샷 저장 / 두 스냅샷 비교 / 드라이브 수정 이력 조회
- `snapshots/<YYMMDD_라벨>/` — 탭별 JSON(표시값 + 수식) + 그 시점 제때 구매정산 CSV
- `YYMMDD_*.md` — 건별 검토 기록

**스냅샷 대상 탭**: 그달_발주진행현황 / 매입사마감 / 신_품목리스트 / 신_단가변동사항 / 종합현황 (월이 바뀌면 `TABS` 첫 항목 수정)
- **정정함 (2026-11-05)**: `중간단가변경이력` 탭은 시트에서 없어졌다 — 현재는 `단가 변동 이력`·`코드변동사항`으로 나뉘어 있다. `sheet_snapshot.py`의 `TABS`에 아직 남아 있어 `snap`이 400 에러로 실패한다(첫 항목도 `10월_발주진행현황`으로 고정) → **스크립트 수정은 [시스템] 세션 몫**
- 단가 근거 확인은 `신_단가변동사항`(코드·적용일·구jt단가 → 신jt단가) 우선, 보조로 `단가 변동 이력`

**⚠️ 매입사마감 탭은 월별 사본이 없는 롤링 탭** (2026-11-05 확인) — 달이 바뀌면 **B3·B4 조회 시작일·종료일 + 표 전체 수식의 참조 탭(`'11월_발주진행현황'!…`)이 함께** 바뀐다(A1의 「기준 시트: 9월_발주진행현황」은 갱신되지 않는 낡은 라벨이니 믿지 말고 수식을 본다). 그래서 **달이 바뀌면 지난달 마감확인·금액대사·지출결의서 상태를 라이브로 볼 수 없고, 되돌리려면 날짜 2칸이 아니라 수식 참조까지 전부 고쳐야 한다**(사실상 불가) → **매달 말 팀장 마감 직후 `snap <YYMMDD>_<N>월마감후`를 반드시 떠 둔다.** 발주진행현황은 달별 탭이 남으니 단가 대조는 사후에도 가능

**매입사마감 집계 기준은 열마다 다르다** (2026-11-05 수식 확인)
- 입고건수·BT공급가액(T)·부가세(U)·매입가(V) = **P 입고일자**가 조회기간 안인 행만 (`SUMIFS … P>=B3, P<=B4`)
- 미입고 = **P가 공란이고 E 입고요청일**이 조회기간 안인 행 (`COUNTIFS … P="", E>=B3, E<=B4`)
- 따라서 ① P가 비어 있으면 금액에 전혀 안 들어간다 ② **E(입고요청일)가 잘못 들어간 미입고 행은 어느 달 미입고에도 안 잡혀 추적에서 빠진다** ③ 참조 탭이 당월 탭 하나뿐이라, 지난달 탭에 남은 중복 행은 집계에 들어가지 않는다(금액 이중 집계 위험 없음)

**사용법** (저장소 루트 기준, 한글 출력 깨지면 `-X utf8`)
- 저장: `python -I -X utf8 purchase_closing/sheet_snapshot.py snap 261019_팀장검토후`
- 비교: `python -I -X utf8 purchase_closing/sheet_snapshot.py diff 261016_검토전 261019_팀장검토후`
  - 결과 유형: 입력변경 / 수식변경 / 수식→값 덮어씀 / 계산결과변경
- 수정자·시각: `python -I -X utf8 purchase_closing/sheet_snapshot.py revs`
- 인증: `C:\Users\BLUETREND\.gdrive-mcp\` OAuth(읽기 전용) — 저장소 밖, 회사 PC에만 있음

**제때 정산 데이터**: ebiz.jette.co.kr → 발주관리 → 구매 정산내역 조회 → 마감월·매입사 블루트렌드 조회. 화면 그리드 `gridCS06100Top_T1._dataSource.getJsonRow(i)`로 읽음(FIX_IN_DATE·ITEMID·FIX_IN_QTY·UNIT_PRICE·SUPPLY_PRICE·VAT)

**검토 기준**
- 단가 비교 대상 = 발주진행현황 W열 jt단가(VAT 별도), X jt매입단가(공급가), Y jt부가세, Z jt매입가
- 제때는 단가 원 단위 반올림 후 × 수량, 시트는 VAT 포함가 ÷ 1.1 미반올림 → 행당 ±100원대 차이는 정상
- 같은 날 같은 코드 ±동량 = 단가 정정, 정상 단가로 −1 = 1개 차감 → 시트에 행 없음, 조정분으로 따로 집계

**행 번호는 기록에 남기지 않는다** (2026-11-05) — 발주진행현황은 중간에 행이 끼어들어 번호가 계속 밀린다(10/28 기준 170행 = 11/5 기준 55행). 검토서·인계 기록에는 **코드 + 입고요청일 + 업체명**으로 적고, 행 번호를 쓸 때는 기준 날짜를 같이 적는다

**입고일(P)이 입고요청일(E)보다 빠른 행** (2026-11-05) — 전월 발주분으로 보고 지우지 않는다. 제때 구매정산 CSV에 그 코드·수량이 **그 달 매입으로 잡혀 있으면 그대로 둔다**
