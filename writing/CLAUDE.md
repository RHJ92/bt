# writing — 업무 커뮤니케이션 교정 거점

카톡·메일 등 **일상 업무 대화의 맞춤법·표현 교정** 작업 공간.
공식 안내문(공급가 조정, 배송 휴무 등)은 `notice/`에서 다루고, 여기는 사람 대 사람으로 주고받는 가벼운 소통이 대상.

부수 목적: 교정 기록을 쌓아 **내 말투 프로파일**과 **자주 틀리는 표현 사전**을 만들고, 반복되는 일상 업무 패턴을 학습 자료로 남긴다.

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `drafts/` | 건별 교정 기록. 파일명 `YYYYMMDD_채널_상대.md` (예: `20260804_카톡_제때물류팀.md`) |
| `style/tone_profile.md` | 내 말투 프로파일 — 상대별 톤, 반복되는 글 습관, 순화 사전 (누적 갱신) |
| `style/자주틀리는표현.md` | 반복 지적된 맞춤법·표현 오류 사전 (누적 갱신) |
| `style/문형_템플릿.md` | 상황별 문형 뼈대 (결재 요청, 개조식 보고, 재요청, 오해 방지 카톡, 소싱 공고 등) |

**교정 전에 `style/` 3개 파일을 먼저 읽는다.** 이미 정리된 반복 오류·말투 특징이 있어 같은 지적을 반복하지 않기 위함.

## 교정 답변 형식 (고정)

1. **교정문을 코드 블록으로** 먼저 — 바로 복사해서 붙여넣을 수 있게
2. 이어서 **수정 포인트 표** — `원문 / 교정 / 이유` 3열
3. 톤 자체를 바꾸는 게 나은 부분이 있으면 표 아래에 한두 줄로만 제안 (강요 X)

원문이 이미 문제없으면 "그대로 보내도 됩니다" 한 줄로 끝낸다. 억지 교정 금지.

## 교정 원칙

- **말투는 보존한다.** 맞춤법·띄어쓰기·비문·중의적 표현만 손대고, 사용자 특유의 어투(예: "~해주시면 감사하겠습니다" 대신 쓰는 실제 표현)는 유지
- 카톡은 카톡답게 — 문어체로 격상시키지 않는다. 메일은 메일답게 — 인사·용건·마무리 구조만 점검
- 업계 용어(축산 부위명, 거래처명, 사내 약어)는 임의로 풀어쓰지 않는다. 애매하면 물어본다
- 상대가 거래처/상사/동료인지에 따라 존대 수준이 달라지므로, 기록 시 상대를 같이 남긴다
- **용건이 맨 뒤에 오면 앞으로 끌어올린다** — 결재자·재무팀은 "나한테 뭘 해달라는 건지"를 먼저 찾는다
- **"문의드립니다"로 시작했는데 본문에 질문이 없는 경우가 잦다** — 요청 문장이 실제로 있는지 확인하고, 없으면 한 줄 추가 후 알린다
- 부정형·감정 표현은 조건형/사실 전달로 순화 (`거래 불가` → `MOQ 이상만 가능`). 순화 목록은 `style/tone_profile.md`
- 뜻이 달라지는 **실질 오타**(임가공비, 10,000만개 등)는 표 밖에서 따로 짚어 확인 요청
- 숫자·금액·일자는 문장에서 빼서 불릿으로. 금액 수정 요청이면 차액도 같이 적는다

## 누적 루틴

교정 건이 끝나면:
- 새로 나온 오류 유형 → `style/자주틀리는표현.md`에 추가 (이미 있으면 발생 횟수만 +1)
- 말투 특징이 관찰되면 → `style/tone_profile.md` 갱신
- 원문이 길거나 나중에 다시 볼 가치가 있으면 → `drafts/`에 건별 파일로 저장. 짧은 한두 문장짜리는 저장 안 해도 됨
