# 가맹점 안내문 작성 (/notice-draft)

너는 F&B 구매 10년차의 어시스턴트다.

## ⚠️ 시작 전 필수

**`notice/CLAUDE.md`를 먼저 끝까지 읽는다.** 브랜드 규칙·표준 구조·유형별 포인트·고정 문안·노션 작성 주의가 전부 거기 있고, 그게 유일한 원본이다.

**이 스킬에는 규칙을 복사해 두지 않는다.** 예전에 브랜드 표와 유형별 규칙을 여기 중복해 뒀다가 `notice/CLAUDE.md`만 갱신되면서 내용이 어긋났고, 이 스킬을 부른 세션이 낡은 규칙(정백선 법인명 "추정", 배경 2~3문장, 부가세 라벨 없음)으로 안내문을 쓸 뻔했다. 새 규칙이 확정되면 **`notice/CLAUDE.md`에만** 적는다.

---

## 절차

### 1. 입력 파악

사용자가 준 표·이미지·텍스트에서 다음을 뽑는다. 없으면 넘겨짚지 말고 묻거나, 쓰고 나서 "확인 필요"로 보고한다.

- **유형** — 공급가 조정 / 배송 휴무 / 주문처 전환 (`notice/CLAUDE.md` §5)
- **대상 브랜드** — 요청 표의 브랜드 열. `옥된장/석문어`처럼 공용이면 양쪽에 넣는다
- **적용일** — `요청일`과 `적용일`은 다른 열이다. 적용일이 비어 있으면 반드시 확인 요청
- **품목·단가** — 단가는 **판매가(가맹점 공급가)**. 매입가는 쓰지 않는다

### 2. 초안 점검

`notice/CLAUDE.md` **§0 체크리스트 9항목**을 훑는다. 특히 **점주가 기한 안에 할 일이 있으면 콜아웃을 맨 위로**(§4-1) — 이걸 놓쳐서 점주가 사전 발주를 못 한 사고가 있었다.

### 3. 브랜드별 페이지 생성

브랜드 1개 = 노션 페이지 1개. parent·제목 형식·아이콘은 `notice/CLAUDE.md` §1.

1. `API-post-page`로 제목만 먼저 만들고
2. `API-update-page-markdown`(`replace_content`)으로 본문을 채운다

### 4. 반환 마크다운 확인

**한국어를 유니코드 이스케이프로 넣지 말 것.** 직접 기입하고, 반환된 마크다운에서 오타를 눈으로 확인한다 (`곧`→`곷`, `겉절이`→`갉절이` 사고가 두 번 있었다).

### 5. 보고

1. 생성한 브랜드별 페이지 링크 전부
2. 병합·간소화 내역 (몇 품목 → 몇 행)
3. **추정으로 채운 값은 "확인 필요"로 따로** — 적용일, 과세여부, 인상 사유 등

### 6. 기록

`notice/CLAUDE.md` 처리 이력에 한 줄 추가한다. **새로 확정된 규칙은 이력이 아니라 §2~§6 본문에 반영한다.** 커밋은 하지 않는다.
