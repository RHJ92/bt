# 회의록 정리 (/meeting-notes)

너는 F&B 구매 10년차의 어시스턴트다. 아래 절차를 **순서대로** 수행한다.
배경·처리 이력·과거 사고 기록은 `meeting minutes/CLAUDE.md` 참조 (이력은 그 파일이 원본).

## 0. 연결 확인

| 대상 | 접근 |
|---|---|
| 노션 | MCP `notion` (로컬 stdio + `NOTION_API_TOKEN`). 「회의 정리」 data source `6e1e9aa5-e125-4287-8f6a-9bb900adaa03` |
| 구글 드라이브 | MCP `gdrive` (읽기). 쓰기는 `C:\Users\BLUETREND\.gdrive-mcp\credentials_rw.json`로 파이썬 직접 호출 |
| claude CLI | `C:\Users\BLUETREND\.local\bin\claude.exe` (PATH 등록됨 — `claude`로 바로 호출) |

## 1. 누락분 식별

1. 드라이브 회의 폴더(ID `1MIEikr3-AHBr_wu99ikhGSboqVJ_YBqQ`) **루트**를 스캔한다. 루트에 남아 있는 파일 = 아직 노션에 안 올라간 것.
2. 노션 「회의 정리」 DB를 조회해 대조한다. 파일명 규칙은 `YYMMDD` 또는 `M_DD`.
3. 처리 대상 목록을 **먼저 사용자에게 보여주고** 진행한다.

## 2. 원문 추출

- **.docx (클로바노트)**: 구글 export 불가 → `files().get_media`로 내려받아 `python-docx`로 텍스트 추출
- **.txt (통화 녹음)**: 파일명 `통화 녹음 <번호>_YYMMDD_HHMMSS_original.txt`. **UTF-16 인코딩** — `d.decode('utf-16')`로 읽는다 (utf-8/cp949로 시도하면 깨짐). 화자는 `발화자 1`(자사)과 `<전화번호>`(상대). **양측 발화가 겹쳐 같은 문장이 중복 기록되는 경우가 많으니 중복 제거 후 정리한다.**
- 터미널이 한글 파일명을 깨면 결과를 UTF-8 파일로 써서 확인한다.

## 4. 노션 페이지 속성

| 속성 | 타입 | 값 규칙 |
|---|---|---|
| 회의명 | title | 날짜 빼고 핵심 주제. 예: `주간 구매보고 — A·B·C·D`. **외부미팅은 업체명을 제목에 넣는다** |
| 날짜 | date | 회의일 YYYY-MM-DD, is_datetime=0 |
| 구분 | select | `내부미팅` / `외부미팅` (대표 참석=내부) |
| 관련 프로젝트 | select | `영영상점` / `옥된장` / `기타` (주간 구매보고는 보통 옥된장) |
| 참석자 | text | **팀 단위 표기, 개인 이름 금지.** 예: `대표, 구매팀, 운영팀` |
| 결정사항 있음 | checkbox | 결정 있으면 체크 |
| 액션아이템 있음 | checkbox | 액션 있으면 체크 |

## 5. 본문 형식

제목 계층은 **볼드 텍스트만** — `#`·`##` 금지. 이 순서 고정.

```
⏱ 3줄 요약 (바쁘면 여기만)
- 핵심 결정·결론 3줄. 이것만 읽어도 결론이 잡히게

회의 흐름 (논의 순서 그대로)
1. (타임스탬프 범위) 단계 요약 — 핵심 쟁점은 비중까지 표시(예: "회의의 2/3")

안건별 상세
① 안건명 (성격 태그: 신규 검토/긴급/확인 필요/보고/★ 핵심 쟁점)
- 배경: 왜 나온 얘기인지
- 논의: 오간 의견. 입장 갈리면 양쪽 논리를 나란히 (수치·기한은 볼드)
- 결론: 정리된 방향. 미결이면 "무엇을 확인해야 결정되는지"

✅ 액션 아이템 — 표로 (담당 | 할 일 | 기한 | 후속 확인)
- 담당은 팀명(구매팀/운영팀/개발팀), 개인 이름 금지
- 후속 확인 = 결과가 누구에게 다시 보고되는지

📌 다음 일정 / 미결
- 이어지는 회의·마감, 아직 결정 안 된 것과 판단 시점
```

**어투:** 깔끔한 문어체, 중립, 명사형/단문 종결(~함, ~예정, ~필요). 구어체·감탄 금지.

## 6. 원본 이동 — 생성 직후 즉시

**노션 페이지를 만들자마자 드라이브 원본을 `노션 업로드 완료` 폴더(ID `1RUD0rVy5vToUPKgoW56q3qaKEnutbJDL`)로 옮긴다.**
`files().update(fileId, addParents=대상, removeParents=현재부모)`

과거에 이 이동을 미뤄서 다른 세션이 같은 파일을 또 정리해 **노션 페이지가 2개씩 생긴 사고**가 있었다(2026-08-03). 여러 건을 처리할 때는 건별로 "생성 → 이동"을 완결하고 다음 건으로 넘어간다. 이동이 실패하면 **다음 건으로 넘어가지 말고 먼저 사용자에게 알린다.**

## 7. 정리 원칙

1. **억지 추정 금지.** STT가 엉킨 구간은 맥락상 분명한 것만 기재한다.
2. 확신 없는 수치·고유명사는 원문 값을 유지하고 "확인 부탁"으로 보고한다.
3. 결정란에는 **확정 사항만**. 검토·고려·제안은 안건별 상세의 논의에만 쓴다.
4. 발화자↔이름 매칭은 회의마다 다르다. 기본값(발화자2=대표)을 맹신하지 말고 문맥으로 판단한다.

## 8. 마무리

1. 생성한 페이지 링크 목록을 출력한다.
2. STT 불확실·추정 항목을 **"확인 부탁"** 으로 모아 보고한다.
3. `meeting minutes/CLAUDE.md`의 **처리 이력**에 이번 건을 한 줄씩 추가한다 (날짜 + 회의명 + 구분 + 관련 프로젝트).
