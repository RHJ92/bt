블루트렌드 마켓봄으로 주문받는 **식기류 + 유니폼·기물 전체**의 입출고 원장과 재고자산을 한 파일에서 관리한다.
기존 식기류·유니폼 두 파일을 통합한 것으로, **이 파일이 현행본**이다. 옛 파일들은 [archive](../archive/)에 격리해 뒀다 — 열어서 입력하지 말 것.

## 파일 — [통합_재고관리(로트기반).xlsx](<통합_재고관리(로트기반).xlsx>)

> ⚠️ **이 파일은 손으로 고친 상태입니다** — 파일명(`마켓봄_재고관리` → `통합_재고관리`)과
> 시트명(`기타재고(수기)` → `월마감(축·수산품 등 취합)`)을 사용자가 직접 바꿨습니다.

## 핵심 구조 — 품목코드 2단

마켓봄은 **유니폼을 사이즈별 개별 상품**으로 등록해 두었고(`반팔 유니폼_M`, ok0011 …),
경인양행 매입원가는 **사이즈가 아니라 구매 시기별**로 갈린다. 그래서 두 축을 분리했다.

| 축 | 단위 | 쓰이는 곳 |
|---|---|---|
| **품목코드** | 마켓봄 상품 1:1 (유니폼은 사이즈별) — 64개 | 원장 입력·출고 대사·창고 실사 |
| **원가품목** | 사이즈 통합 (브랜드+품목) — 46개 | 로트·재고자산 평가·선입선출 |

원장 F열 `원가품목(자동)`이 품목 마스터에서 자동으로 끌어온다(수식, 3,000행 미리 채움 — 손대지 말 것).
품목코드를 잘못 적으면 `❌코드확인`이 뜨고 셀이 빨갛게 표시된다.

**왜 이렇게 나눴나** — 경인양행 재고는 사이즈별 수량은 알지만(2026-08-28 실사) 각 사이즈가
어느 매입 시기 원가인지는 알 수 없다. 원가층을 사이즈까지 쪼개면 없는 근거를 지어내야 해서,
**수량은 사이즈별로, 원가는 품목별로** 관리한다.

## 과세 / 면세 구분

- **재고자산은 전부 공급가액(부가세 별도) 기준**이다. 식기류·유니폼 단가 모두 확인 완료
  (예: 디저트접시 2,327.27 × 1.1 = 2,560).
- **품목 마스터 G열 `과세구분`** 이 기준점. 로트 마스터·재고 현황·월말 대사·월마감이 전부 이 값을 자동으로 물어온다.
- 현재 64품목 전부 `과세`. **축산품·수산품이 편입되면 품목 마스터 G열에 `면세`만 입력**하면
  로트 마스터 과세/면세 소계, 재고 현황 브랜드별 과세·면세 자산, 월마감 요약이 자동으로 갈린다.

## 소유법인과 이관 기준일 (2026-09-01)

**2026-08-31까지** 재고는 블루트렌드·옥된장에프엔비·석문어에프엔비·정백선에프엔비 **4개 법인에 나뉘어** 있었다.
**2026-09-01자로** 옥된장·석문어·정백선 재고를 전부 블루트렌드로 이관했다 — 근거는 [transfer_260831](../transfer_260831/) 견적서·명세서.

**이관 대상은 유니폼·기물 16로트뿐이다.** 식기류 35로트(삼보물류)는 **2025-06 블루트렌드가 옥된장에서 인수한 뒤
줄곧 BT 재고자산이었고 앞으로도 그렇다** — 이관 대상이 아니다.
로트 마스터 D열 매입처의 `옥된장 인수(이관)`·`옥된장 구매(유진)→BT 매도`는 **2025년 당시 매입 경로 표기일 뿐
소유법인이 아니다**(20로트). 소유는 G열이 기준이고, 식기류 35로트 전부 `블루트렌드`다.

이관은 **수량이 움직인 게 아니라 소유와 평가액이 바뀐 것**이라 원장에 행을 넣지 않고 로트 속성으로 처리한다.

| 로트 마스터 열 | 내용 |
|---|---|
| `소유법인(~26.08.31)`(G) | 2026-08-31까지의 소유 — 블루트렌드(식기류 35로트) / 옥된장 8 / 석문어 4 / 정백선 4 |
| `브랜드 매입단가`(H) | 브랜드가 경인양행·온라인몰에서 산 원가 → **8월말까지 평가 기준** |
| `BT 취득단가`(I) | 브랜드 원가 ÷ 0.99 (마진 1%) → **9/1부터 평가 기준** |

「월말 대사」 시트의 **B1 기준일**이 스위치다. 기준일이 `2026-08-31` 이전이면 소유법인이 법인별로 갈리고
브랜드 매입단가로, `2026-09-01` 이후면 전부 블루트렌드·BT 취득단가로 자동 전환된다.
「재고 현황」은 항상 현재 시점(이관 후) 기준이라 전액 블루트렌드다.

## 월말 대사 시트 열 구성

**왼쪽(A~J) = 로트별 재고자산 확정 + 삼보물류 로트 대조**
`로트번호 / 원가품목 / 과세구분 / 소유법인(기준일) / 기준일 잔량 / 적용단가 / 자산(기준일) / 삼보물류 로트 회신(입력) / 차이 / 매입일`
삼보물류는 **로트번호 단위로 재고현황을 회신**하므로 H열에 붙여넣고 I열 차이 0을 확인한다(식기류 기존 방식).
경인양행·본사창고는 로트 단위 회신이 없어 이 칸을 비워 둔다.
아래에 **소유법인 4개 소계 + 과세/면세 소계 + 합계** 행이 붙는다.

**오른쪽(L~Q) = 경인양행·본사창고 실사 대조** (유니폼·기물 30품목만)
`품목코드 / 경인양행(장부) / 본사창고(장부) / 경인양행(회신) / 본사창고(회신) / 차이`
두 창고는 **품목(사이즈)별로 실사**하므로 여기서 대조한다.

> 이전 버전에는 오른쪽에 `삼보물류(장부)·삼보물류(회신)` 열이 있었는데, 삼보는 왼쪽 로트 대조로 처리하므로
> **중복이라 삭제**했다. 식기류 34품목도 오른쪽에서 뺐다(경인양행·본사창고에 재고가 없어 전부 0이었음).

## 월마감(축·수산품 등 취합) 시트 — 마켓봄 외 재고

마켓봄으로 운영하지 않지만 **블루트렌드·영영상점 재고자산으로는 잡아야 하는 것들**.
고정 품목이 아니라 있다 없다 하므로 **로트를 걸지 않고 매달 수기로 입력**한다.

`마감월 / 사업자 / 품목명 / 과세구분 / 단위 / 수량 / 단가(공급가액) / 재고자산(공급가액) / 재고자산(VAT 포함) / 검증 / 보관처·비고`
H·I열만 수식이다 (H = 수량 × 단가, I = 면세면 H 그대로 / 과세면 H + 10%).
사업자·과세구분·검증은 드롭다운, 400행까지 준비돼 있다.

2026-08 기준 37행을 「2600905_구매파트_8월 마감 재고자산」 `26.08`에서 옮겨 채웠다.

|---|---|---|---:|
