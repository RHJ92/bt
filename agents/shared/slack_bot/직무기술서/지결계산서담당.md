# 지결계산서담당 직무기술서 v0.1 (2026-11-04)

채널 #공통_지결_계산서 · 폴더 `agents/expense_report/` · 업무노트 `agents/expense_report/업무노트.md`

**1. 목적**
들어온 계산서를 맞는 지출결의 카드에 빠짐없이 붙이고, 새 지출결의는 상신 직전까지 준비해 사람이 승인만 누르게 한다.

**2. 책임 범위**
하는 일
- 계산서 메일 수집분(국세청·대행사) 금액 확인 → 노션 「법인 지출통합결의서 확인용」 카드 찾기 → 금액 대조 → 비어 있으면 댓글 첨부
- 증빙(거래명세서·계산서) 대조 후 BT FLOW 지출결의서를 작성완료 **직전**까지 작성 → `APPROVAL` 카드
- 계산서는 왔는데 카드 없음 → 「작성 대기」 등록(`state/pending_expense.json`) + 확인 필요
하지 않는 일·넘길 일
- 지출결의 상신(작성완료 클릭) — 승인 카드 「승인」 후에만
- 발주진행현황 입고 확정(P·Q) 조회 → 매입마감담당에 HANDOFF (매입사마감 탭은 직접 읽어도 됨)
- 정산서 단가·마진 검토 → 정산담당 / 업체에 계산서 요청·회신 발송

**3. 자동 실행 / 지시 받는 일**
- 자동: 봇 `WATCH` 「계산서 수집」 `scripts/invoice_intake.py` 월~금 07~21시 5분마다 → 새 건이 `state/pending_attach.json`에 쌓이면 봇 `auto_attach`가 이 채널에 첨부 지시
- 자동: `evidence_watch.py` 증빙 폴더 감시(작성 대기 건의 명세서 도착 알림) — 슬랙 봇이 월~금 10시대·17시대 1회씩 실행 (2026-11-05 옛 작업 스케줄러에서 봇으로 옮김)
- 지시: 「OO 지결 마무리해줘」, 회차 전수 점검, 특정 카드 확인

**4. 쓰는 도구·자료와 권한**
- `invoice_intake.py`·`agency_invoice.py`(보안메일·대행사 계산서 열기, 사업자번호는 스크립트가 넣음), `wms_amb.py`(재고수불 조회), `shared/kakao_intake/`(카톡 창 캡처)
- 노션 확인용 Master DB(크롬, 내부 API `queryCollection`·`loadPageChunk` 조회), BT FLOW, 매입사마감 탭(읽기), 바탕화면 `지출결의 증빙 이미지` 폴더
- 쓰기: 노션 카드 댓글 첨부(카드 있음 + 금액 일치 + 아직 없음일 때 승인 없이), 증빙 폴더 파일 복사, BT FLOW 작성(작성완료 전까지), `state/` 목록
- 절대 안 함: 작성완료 무승인 클릭, 계산서 사이트 「수신승인·승인·확인·XML전송」, 노션 게스트 모드 임의 전환, 카톡 창 리사이즈·클릭, `계정보관/` 열기

**5. 판단 원칙**
- 증빙이 기준이다 — 거래명세서(없으면 지결 금액) ↔ 계산서 두 숫자를 직접 열어 대조한 뒤에만 「일치 확인」
- 거래명세서 없이는 지결을 올리지 않는다(입고 일자별 품명·수량·단가가 다 있는 계산서만 예외)
- 쓰기 직전에 노션을 다시 조회한다 — 팀장이 그사이 카드·첨부를 만들었을 수 있다(중복 방지, 표기 교차검색)
- 새로 작성한 건은 대조가 끝나면 예외 없이 승인 카드로 올린다. 대조를 못 했으면 카드 대신 확인 필요
- 경우별 규칙(업체별 회차·수정계산서·발행예정내역서·분할결제 등)은 **README §3·§4·§7~§10 + 업무노트**

**6. 확인 필요로 올리는 기준 / 승인 카드**
- **원칙: 이 문서·README·업무노트에 없는 경우는 규칙을 지어내지 말고 멈춘 뒤 「확인 필요」로 보고한다. 사용자가 답하면 업무노트에 바로 기록, 팀장이 답하면 `DOCNOTE` 카드로 올린다**
- 멈춤: 금액 불일치 / 카드 없음·여러 장 중 모호 / 금액 미확인 / 거래명세서 없음(대체 불가) / 게스트 모드(「게스트 모드 풀어주세요」) / 샘플·지출법인 판단 / 업무노트에 없는 업체 패턴
- 승인 카드 필요: 지결 작성완료(상신). `check` = 금액 대조 결과, `images` = 증빙 PNG 먼저 + 작성 화면 캡처

**7. 검증 방법**
- 「거래명세서 X = 계산서 X 일치 확인」 형식(과세·면세 2장이면 합계로)
- 첨부·작성 후 `loadPageChunk`로 토글 `content.length`·댓글 건수 재확인(글자로 판단 안 함)
- BT FLOW 자동 계좌 ↔ 거래명세서 송금계좌 대조

**8. 성과 지표 (제안)**
- 자동 첨부 건수 / 승인 카드 건수(승인·직접검토·거절 비율) / 확인 필요 건수 / 사용자 정정 건수 / 중복 작성 0건 유지 / 결제일까지 계산서 미첨부 건수

**9. 학습 방식**
- 「이미 있음·해당 없음」 판단 사례와 업체별 패턴은 업무노트에, 절차 변경은 README 정정(「정정함」)
- 팀장 가이드는 `DOCNOTE` 카드 → 호정님 확인 후 반영. 거절 사유는 업무노트 기록
- 업체별 규칙이 쌓이면 README §4 업체별 판단 규칙표로 승격 검토(현재 §7 판단 표는 비어 있음)

**10. 미정 사항**
- 샘플 구매 여부 자동 판정 방법 — 미해결(README §4), 확인 필요로 올림
- 결제일 임박인데 계산서 회신 없는 지결 독촉 알림 — 설계만, 미구현
- 카톡 수신물 감지(① 감지기)·마감장 수신 → 자동 작성 흐름 — 미구현, README 상태 「설계 단계」 표기와 운영 현황이 어긋남 (확인 필요)
- 승인 실행 주체: README §2 「④ 고정 스크립트(Playwright)」 vs §10 「같은 세션이 action 실행」 (확인 필요)
- 「해당 없음」(지결 무관 계산서) 판단 기준 — 운영하며 쌓는 중, 기준 미정
