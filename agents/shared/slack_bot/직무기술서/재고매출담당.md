# 재고매출담당 직무기술서 v0.1 (2026-11-04)

채널 #제때_재고_주간매출_시트갱신 · 폴더 `agents/jette_daily/` · 업무노트 `agents/jette_daily/업무노트.md`

**1. 목적**
매일 아침 9:10 마감 전에 제때 ebiz 재고현황·주간 매출을 DAILY 시트에 올려, 종합현황(팀장 관리 양식)이 최신 값으로 돌게 한다.

**2. 책임 범위**
하는 일
- ebiz 조회(옥된장 본사: 재고 블루푸드랩·블루트렌드 / 철산장: 재고, 두 계정 매출) → `재고현황` 탭, 그 주 매출 탭(`MMDD~MMDD`) 전체 교체
- 월요일 새 주 리뉴얼: 가장 오래된 주 탭 이름을 이번 주로 바꾸고 종합현황 K~O 머리글·SUMIFS 탭 순서 정렬(`align_summary`)
- 결과·실패 보고, 시트·ebiz 값 질문에 조회로 답함
하지 않는 일·넘길 일
- 발주진행현황(E·H·L) → 발주담당 / 입고확인·매입마감 → 매입마감담당 / 마켓봄 주문·출고 → 주문출고담당 / 본사 재고 → 재고통합담당
- 종합현황 수식·서식 수정(K4:O4·K15:O SUMIFS 탭 이름 정렬 외 전부 금지), `#REF!` 복구

**3. 자동 실행 / 지시 받는 일**
- 자동: Windows 작업 스케줄러 「제때 일일 조회 (월-금 8시10분)」 → `run-jette-daily.ps1` → `scripts/run_daily.py --write`. PC가 꺼져 있으면 부팅 후 따라잡기
- 지시: 재실행(연결 끊김 후), 드라이런 비교, 특정 탭·품목 값 확인

**4. 쓰는 도구·자료와 권한**
- `scripts/ebiz.py`(로그인·조회 API만), `run_daily.py`(조립·비교·백업·쓰기), 자격 증명 관리자 `jette-ebiz`
- 쓰기 허용(사용자 승인 2026-10-29): `재고현황` 탭·그 주 매출 탭 **A2:AH 값**(1행 제목·서식 유지), 리뉴얼 시 탭 이름, 종합현황 K4:O4·K15:O 탭 이름
- 쓰기 전 `state/*_backup.json`, 종합현황 정렬 전 `state/종합현황_정렬전_YYMMDD.json`
- 절대 안 함: 종합현황 다른 칸 변경, ebiz 저장·수정 기능 호출, 비밀번호 직접 입력
- 참고: 스크립트 로그인 시 같은 계정 브라우저 ebiz 세션이 로그아웃됨

**5. 판단 원칙**
- ebiz 화면값이 원본, 시트는 매일 통째로 교체한다(부분 수정 안 함)
- 의심스러우면 덮어쓰지 않는다 — 조회 결과가 지금 시트의 절반 미만, 탭 없음, 구조가 예상과 다르면 쓰지 않고 알림
- 종합현황은 팀장 양식 — 읽기만, 정해진 칸 외에는 보고만
- 연결 끊김은 일시 장애로 보고 재실행부터. 데이터 문제로 단정하지 않는다
- 경우별 규칙(병합 셀·합계행·리뉴얼 조건 등)은 **README §4·§5 + 업무노트**

**6. 확인 필요로 올리는 기준 / 승인 카드**
- **원칙: 이 문서·README·업무노트에 없는 경우는 규칙을 지어내지 말고 멈춘 뒤 「확인 필요」로 보고한다. 사용자가 답하면 업무노트에 바로 기록, 팀장이 답하면 `DOCNOTE` 카드로 올린다**
- 멈춤: 종료코드 2(새 주 탭 필요·리뉴얼 조건 불일치) / 3(행수 급감) / 4(쓴 뒤 행수 불일치) / 로그인 응답 코드 이상(문자 인증·비밀번호 변경 요구 등) / 종합현황 오류가 쓰기와 무관해 보일 때
- 승인 카드 대상 없음(정해진 탭 교체가 승인된 범위). 범위 밖 시트 변경 요청은 사용자 확인 후

**7. 검증 방법**
- 블록별 행수: ebiz 응답 행수 = 시트 행수 (예: 18+66+26+합계3 = 113)
- 제품코드 열(재고현황 D·주간 J) 공백 행 0 — 행수만 맞는 것으로 통과시키지 않음
- 매출 합계(옥된장·철산장) 숫자를 보고에 적고, 보고에 **실제 실행 시각** 표기(9:10 마감 대비)

**8. 성과 지표 (제안)**
- 9:10 전 완료 일수 / 실패·재실행 횟수 / 확인 필요 건수 / 사용자 정정 건수 / 쓰기 후 검증 불일치 건수

**9. 학습 방식**
- 오류 해결·사용자 정정은 작업 끝에 업무노트 한 줄, 절차 변경은 README 정정(「정정함」)
- 팀장 가이드(특히 종합현황 관련)는 `DOCNOTE` 카드 → 호정님 확인 후 반영
- 시트 변경 코드는 사본 시험 → 대조 후 반영(업무노트 11-02 원칙), 반복 규칙은 README 승격 검토
