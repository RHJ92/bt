## 1. 카톡 MCP 소스 검토 결과 (2026-10-27)

**대상**: [kronenz/kakaotalk-mcp](https://github.com/kronenz/kakaotalk-mcp) v0.2.0 (MIT, Python, Windows 전용). 마지막 커밋 2026-03-22, Glama 표시 "Inactive", 개발 단계 Alpha. 전체 2,400줄 정도라 핵심 파일(`controller.py`·`server.py`·`config.py`)을 다 읽었다.

**보안 — 문제 없음**
- 외부 통신 코드 없음 (requests·urllib·socket 등 import 없음). MCP 표준 입출력(stdio)으로만 Claude와 통신
- 의존성은 `mcp`, `pywin32` 두 개뿐
- 외부 프로그램 호출은 이미지 보내기 기능의 PowerShell 이미지 변환 1곳뿐 (읽기에는 안 쓰임)
- 파일 쓰기는 이미지 다운로드 시 지정 폴더로 복사하는 것뿐

**동작 방식의 한계 — 이게 실제 걸림돌**

| 항목 | 실제 동작 | 영향 |
|---|---|---|
| 메시지 읽기 | 채팅창을 **맨 앞으로 띄우고 마우스 클릭 → Ctrl+A → Ctrl+C** 후 클립보드를 읽음 | 실행 순간 **사용자의 창 포커스·마우스·클립보드를 뺏는다.** 작업 중 복사해 둔 내용이 사라질 수 있음 |
| 읽기 전제 | 채팅방 창이 **이미 열려 있어야** 읽힘 (없으면 Ctrl+F 검색으로 열기) | 감시할 업체방을 열어 둔 채 운영 |
| 키워드 모니터 | 위 읽기를 **기본 5초마다** 반복 | 업무 중 사용 불가 수준. 쓰지 않는다 |
| 이미지 다운로드 | 카톡 **전체 캐시**에서 최근 이미지 N개 복사 — **방 구분 없음** | 개인 대화 사진도 섞여 들어옴. 어느 업체 건인지 판단 불가 |
| 파일(PDF·엑셀) | 지원 안 함 (이미지 캐시만) | PDF 마감장은 못 잡음 |
| 보내기 도구 4개 | 메시지·일괄·멘션·이미지 전송 | **반드시 차단** |

**판단** — 악성 코드는 없지만 "감지기"로 상시 돌리기엔 부적합하다. 쓴다면:
1. PyPI(`uvx kakaotalk-mcp`)가 아니라 **검토한 커밋(7b41dd9)을 그대로 소스 설치** — 배포본이 소스와 같다는 보장이 없음
2. 보내기 도구 4개(`kakao_send_message`·`kakao_send_bulk`·`kakao_send_mention`·`kakao_send_image`)와 모니터 도구는 settings 권한에서 **deny**
3. 읽기는 **하루 2~3회, 자리 비운 시간**(점심·퇴근 전)에만. 사용자 클립보드 덮어쓰기 감수
4. 파일·이미지 수집은 이 MCP 대신 **PC 카톡 받은 파일 폴더 감시**로 (→ 사용자 판단으로 폐기, §2 참고)

## 2. 카톡 수신 감지 방법 조사 (2026-10-27)

| 경로 | 결과 |
|---|---|
| Windows 알림 기록(`wpndatabase.db`)으로 수동 감지 | ✗ — PC 카톡은 Windows 알림 센터를 안 쓰고 자체 팝업을 띄워 기록이 남지 않음 (메일·팀즈·크롬만 있음) |
| 카톡 로컬 대화 DB(`chatLogs_*.edb`) | ✗ — 암호화돼 있음. 풀어 읽는 건 하지 않는다 |
| 받은 파일 저장 폴더 | ✗ — 사용자가 저장을 눌러야 해서 무의미 (사용자 판단) |
| 카톡 MCP 읽기 + 이미지 캐시 시각 대조 | △ — 유일하게 사람 손 없이 되는 경로. 방 텍스트의 "사진/파일" 시각과 캐시 이미지 수정시각을 맞춰 어느 방 이미지인지 판정. 단 읽을 때 화면·클립보드를 뺏으므로 **정해진 시각(점심·퇴근 전) 순회** 또는 슬랙에서 "카톡 훑어줘" 명령 시 실행 |

**수신 시험 결과 (2026-10-27 14:50경, 방 안 연 채로 사진 1장 수신)**
- 이미지 캐시(`chat_data/cli/thumbnail`·`mci_v2`·`oci_v2`·`cli_http_v2`)에 **새 파일 없음** → 사진은 **방을 열어야** 캐시에 내려온다. 캐시 감시만으로는 감지 불가
- 대신 **`chat_data/chatLogs_<채팅방ID>.edb-wal` 파일의 수정시각이 바뀜** → 내용은 암호화라 못 읽지만 **"어느 방에 새 메시지가 왔다"는 신호는 화면 안 건드리고 얻을 수 있다**
- 결론 — 감지 2단 구조:
  1. **신호**: 등록한 업체방의 `chatLogs_<ID>.edb-wal` 수정시각 감시 (상시, 무소음)
  2. **확인**: 신호 온 방만 카톡 MCP로 열어 텍스트 읽기 → 사진·파일 있으면 그때 캐시에 내려온 이미지 수집·분류 → 슬랙 질문. 화면을 잠깐 뺏으므로 즉시 실행할지/순회 시각에 몰아서 할지 사용자 선택
- 필요한 준비: **채팅방ID ↔ 방 이름 대응표** (업체방마다 한 번씩 메시지 오는 순간 어느 파일이 바뀌는지로 매칭)

**사용자 확인 필요**
- 감시할 업체 단톡방·1:1방 목록
- 순회 시각 (예: 12:00, 17:30) — 그 시각엔 PC를 쓰지 않는다는 전제

## 3. 창 캡처 시험 (2026-10-30, 가야김치 단톡방)

- **열려 있는 방 창은 `PrintWindow`(user32)로 앞으로 안 띄우고 캡처됨** — 포커스·마우스·클립보드 안 건드림, 다른 창에 가려져도 됨. 카톡 MCP의 Ctrl+A·C 방식의 대안. 글자는 이미지로 보고 읽음
- 방 창은 `EnumWindows`로 제목(방 이름)과 함께 찾음 (클래스 `EVA_Window_Dblclk`). pywin32 없이 ctypes로 가능. 방 창이 **닫혀 있으면 이 방법은 못 씀**
- 정정: 자식 창은 있음. 첫 시험의 빈 목록은 방 창이 이미 닫힌 뒤였기 때문. 대화 목록 = `EVA_VH_ListControl_Dblclk`, 메시지 입력칸 = `RICHEDIT50W`(**입력·클릭 절대 금지**), 스크롤바 = `_EVA_CustomScrollCtrl`
- **방 찾기·열기 성공**: 메인 창 앞으로 → 앞에 있는지 확인 → Ctrl+F → 유니코드 입력 → 결과 캡처로 확인 → 다시 앞에 있는지 확인 → Enter (`kt_search.py`, `kt_enter.py`). 이 단계만 화면을 뺏음. Enter는 메인 창이 앞일 때만
- **백그라운드 스크롤 성공**: 대화 목록 컨트롤에 `WM_MOUSEWHEEL` 전송. 앞으로 안 띄움. 위·아래 이동량이 달라 캡처로 위치를 다시 확인해야 함
- **파일 저장 자동 클릭 성공**: 캡처에서 「저장」 위치를 찾아 대화 목록 컨트롤에 `WM_LBUTTONDOWN/UP` 전송 → `문서\카카오톡 받은 파일`에 저장, 앞으로 안 띄움. `261022_가야김치_A-type(일반).xlsx`(9.57KB) 저장·열기 확인. 파일 이름이 카톡 표시명 그대로라 어느 방 파일인지 맞출 수 있음. 저장한 파일은 「열기 · 폴더 열기」로 표시가 바뀌어 중복 저장 방지 가능
- **명세서 사진은 썸네일 캡처만으로 금액 읽힘**: 10/23 가야김치 명세서 합계 256,200 = 29,600 + 118,400 + 59,200 + 49,000, 공급자 791-94-01894, 공급받는자 524-88-01177(블루푸드랩). 원본 저장(이미지 뷰어 열기)은 미시험. 작은 숫자는 오독 위험이 있어 증빙용 고화질 원본 확보는 별도 시험 필요
- 스크롤 신호는 창을 닫지 않음(5회 전송 후 창 유지 확인). 첫 시험 때 창이 닫힌 건 다른 원인
- 시험 스크립트: `scripts/`
- 남은 일: 「저장」 위치 자동 판별(지금은 사람이 캡처를 보고 좌표 지정), 감시 방 목록, 순회 시각, 사진 원본 저장

## 5. 공용 도구 `kakao.py` (2026-11-06)

슬랙 담당·VS Code 세션 누구나 쓰는 카톡 **읽기·저장** 도구. 보내는 기능은 없다(입력칸 `RICHEDIT50W` 좌표는 거부).

**순서 (사용자 승인 2026-11-06)**: ① `shot`(캡처)으로 어떤 서류인지 판별 → ② 사업자번호·금액처럼 **숫자가 필요할 때만** `save-file`·`save-photo`로 원본 저장 → ③ 다른 근거와 대조(국세청 보안메일이 그 번호로 열리는지, 명세서 합계 = 계산서 금액 등). 썸네일 숫자만으로 확정하지 않는다

| 명령 | 하는 일 | 화면 |
|---|---|---|
| `kakao.py rooms` | 열린 방 창 목록 | 안 뺏음 |
| `kakao.py open "방이름 일부"` | 메인 창 검색(Ctrl+F) → Enter로 방 열기, 원래 최소화였으면 다시 최소화 | **몇 초 뺏음** |
| `kakao.py shot "방"` | 방 창 캡처 → `state/shots/` PNG 경로 출력 → Read로 봄 | 안 뺏음 |
| `kakao.py scroll "방" up 5` / `down 5` / `bottom` | 대화 스크롤 | 안 뺏음 |
| `kakao.py save-file "방" x y` | 캡처 PNG에서 본 「저장」 글자 좌표 클릭 → `문서\카카오톡 받은 파일\` 경로 출력 | 안 뺏음 |
| `kakao.py save-photo "방" x y` | 사진 더블클릭 → 뷰어 다운로드 → 저장 창 「저장」 → 뷰어 닫기 → 원본 경로 출력 | 뷰어·저장 창이 잠깐 앞으로 |

**시험에서 알게 된 것 (2026-11-06, 에이치엠푸드 방)**
- 보조 모니터(배율 100%, 주 모니터 125%)에 있는 방 창은 「저장」 클릭이 안 먹음 → `save-*`는 방 창이 보조 모니터에 있으면 주 모니터로 옮기고(앞으로 안 띄움) 멈춘다 — `shot`을 다시 찍어 좌표를 새로 정하고 다시 실행
- 업체(친구 아닌 사용자)가 보낸 **파일**은 「친구가 아닌 사용자가 보낸 파일은 안전하지 않을 수 있습니다. 다운로드 받으시겠습니까?」 창이 뜬다 → 방 이름이 「블루 & 」(업체방)이면 확인, 그 밖의 방이면 취소하고 「사람이 직접 저장」으로 보고. 사진은 이 창이 안 뜸
- 사진 우클릭 메뉴는 백그라운드 메시지로 안 뜸 → 뷰어 경로를 씀. 저장 창 파일 이름 칸은 메시지로 바꿔도 무시 → 카톡 기본 이름(`KakaoTalk_날짜_시각.확장자`)으로 저장, 원본 해상도(등록증 사진 5273×7714)
- 저장한 파일은 말풍선이 「열기 · 폴더 열기」로 바뀜 = 이미 저장됨
- 캡처는 `state/shots/`(깃 미추적) — cleanup.py가 3일 지나면 `_삭제대상/`으로

### 5-1. 보내기 `kakao.py send "방" "글" --confirm` (2026-11-06 사용자 「카톡 발송은 류호정 계정으로 에이전트가 한다」)

- `--confirm` 없으면 미리보기만. 방 이름은 열린 방 중 하나에만 맞아야 함. 입력칸에 사람이 쓰던 글자가 있으면 보내지 않음(빈 칸은 「메시지 입력」 안내 글자를 돌려줌)

- 원인: 카톡은 **사람이 입력칸을 클릭하고 붙여넣기/타이핑했을 때만 「전송」을 켠다**. 안 된 방법 — WM_SETTEXT·WM_CHAR(창이 앞이어도), 백그라운드 Enter(PostMessage 무시 / SendMessage는 줄바꿈만), 키보드 End·Enter·글자(한글 IME 조합으로 들어감), 창 크기 흔들기. 11/6 오전 씨에버상사·경기서부 「.」은 우연히 켜진 상태에서 눌린 것

- 첫 실발송: 2026-11-06 14:20 씨에버상사·14:24 경기서부미곡처리장 「.」(마감 요청 시뮬레이션, 사용자가 삭제)
