# expense_report — 지결 자동화 설계 (슬랙 승인형)

**목표**: 사용자는 슬랙 창 하나만 켜 둔다. 마감장·계산서가 들어오면 에이전트가 검토하고 BT FLOW 양식을 **작성완료 직전까지** 채운 뒤, 슬랙에서 승인/거절 버튼으로 묻는다. **승인한 건만** 상신된다.

**큰 그림 (2026-10-27 사용자 확정)** — 지결은 첫 번째 업무일 뿐이고, 실제로 만들 것은 **카톡 수신물 분류 에이전트**다.
- 카톡으로 온 이미지·파일을 **마감장 / 세금계산서 발행 회신 / 계약서 / 품질(클레임) 사진 / 공지 / 기타**로 분류 → 슬랙으로 "OO에서 마감장이 왔어요. 어떻게 처리할까요?" 질문 → 사용자가 고른 처리를 해당 거점 절차로 실행
- 사용자가 직접 "저장하기"를 눌러야 하는 방식은 의미 없음 — 그럴 거면 그 자리에서 직접 작성하는 게 빠르다. **수신 감지는 사람 손 없이** 되어야 한다
- 슬랙: **개인 슬랙**(회사는 슬랙 도입 계획 없음). 테스트로 시작해 문제없으면 그대로 개인 업무 채널로 사용. 개인적으로 할 수 있는·하고 있는 업무들을 이 채널의 에이전트로 계속 붙여 간다
- **재무팀 등 다른 부서에 요청·협조를 구하는 설계는 금지.** 사용자 혼자 가진 권한·도구로만 구성

**지결 업무의 실제 2단계 흐름** (자동화가 둘 다 처리해야 함)
1. **마감장(명세서) 수신 → 지결 작성·상신.** 계산서가 아직이면 증빙 미제출 사유 `댓글 첨부하겠습니다.`
2. **계산서 발행 회신 수신 → 해당 지결 찾아 노션 「확인용」 카드에 댓글로 첨부.** 지결 작성자가 업체에 계산서 발행을 확인받고(메일·카톡으로 발행 이미지 회신) **결제일 전까지** 붙이는 게 원칙. 슬랙 예: "케이엠에스 10월 계산서 회신 왔어요. 10/30 결제 지결(374,466)에 댓글 첨부할까요? [승인]"
   - 결제일이 다가오는데 계산서 회신이 없는 지결은 슬랙으로 독촉 알림 (업체에 요청할지 묻기)

- 작성: 2026-10-27 / 상태: **설계 단계** (아무것도 설치·연결 안 함)
- 커리큘럼상 위치: 2단계 「Slack 슈퍼팀」 첫 실전 과제
- 기존 수동 절차는 [월간_지출결의_작업절차.md](../../memo/지출결의서_자동입력/월간_지출결의_작업절차.md)·[BT_FLOW_작성절차.md](../../memo/지출결의서_자동입력/BT_FLOW_작성절차.md)가 원본. 이 문서는 그 절차를 **누가(어느 부품이) 언제** 돌리는지만 정한다.

## 1. 슬랙에서 보이는 흐름 (완성 모습)

```
🤖 케이엠에스패밀리 마감장이 카톡으로 왔어요. 검토하고 지결 작성할게요.
🤖 지결 작성 완료 — 검토 결과
   · 명세서 374,466 = 계산서 374,466 ✅
   · 노션 중복: 팀장님 등록 건 없음 ✅
   · 이체요청일 10/30 (캘린더 「지출결의」) ✅
   · 특이: 전미수 336,528 포함된 명세서 → 이번 건만 반영
   지출결의 올릴까요?   [승인] [거절] [수정 요청]
👤 [승인]
🤖 상신 완료. 노션 「이체 대기」 등록 확인했어요.
```

- **거절** → 작성 중인 양식 폐기, 사유 기록
- **수정 요청** → 스레드에 사용자가 적은 내용(예: "샘플이니 지출목적 바꿔줘")을 반영해 다시 작성 → 다시 승인 요청

## 2. 부품 4개와 역할 분리

| 부품 | 하는 일 | 구현 | AI 여부 |
|---|---|---|---|
| ① 감지기 | 새 마감장·계산서 찾기 | 카톡 감지([../shared/kakao_intake/](../shared/kakao_intake/README.md)) · 메일 · 증빙 폴더 감시. 일정 간격 실행 | 아니오 (규칙) |
| ② 작업 에이전트 | 대조 검토 → 노션 중복 확인 → 양식 작성(작성완료 직전) → 검토 결과 요약 | `claude -p` 무인 실행 (주간 시세 자동화와 같은 방식) | **예** |
| ③ 슬랙 봇 | 알림·버튼 표시, 클릭 수신, ②④ 호출 | 회사 PC 상시 실행 파이썬 (Slack Bolt, **Socket Mode** — 외부 서버·공개 주소 불필요) | 아니오 |
| ④ 실행기 | **승인된 건만** 작성완료 클릭 → 노션 등록 확인 | 고정 스크립트 (Playwright) | 아니오 |

**왜 ④를 AI와 분리하나** — 지금 작성완료가 막히는 건 AI가 *스스로* 돈 나가는 버튼을 누르려 해서다(권한 분류기 차단). 사람이 슬랙에서 승인한 건을 **정해진 스크립트가 그 한 건만** 누르면 판단은 사람, 준비는 AI로 책임이 분명해진다. ②에는 상신 권한을 끝까지 주지 않는다.

## 3. ② 작업 에이전트의 검토 항목

승인 요청 메시지에 항목별 ✅/⚠️로 표시한다. ⚠️가 하나라도 있으면 작성하지 않고 "확인 필요"로만 알린다.

| # | 검토 | 근거 |
|---|---|---|
| 1 | 명세서 금액 = 계산서 금액 (면세/과세 구분 포함) | 증빙 이미지 |
| 2 | 명세서 금액 = 매입사마감 시트 / 발주진행현황 | 월간 작업절차 「금액 확정 두 갈래」 |
| 3 | **노션 중복** — 같은 업체·금액·이체요청일 건이 요청자 무관하게 있는지 (팀장님 등록분 포함) | 「확인용」 Master DB 검색 |
| 4 | 이체요청일 = 캘린더 「지출결의」 일정, 업로드 마감(전날 12:30) 안 지났는지 | 캘린더 |
| 5 | 지출법인 — 샘플은 블루트렌드가 아닐 수 있음(예: 철산장) | 업체별 규칙표 §4 |
| 6 | 미수금 — 명세서 총미수 말고 **당월(해당 건) 금액만** | 업체별 규칙표 §4 |
| 7 | 계산서 유무 → 없으면 증빙 미제출 사유 `댓글 첨부하겠습니다.` | BT_FLOW_작성절차 |

## 8. 증빙 원칙과 「작성 대기」 감지 (2026-10-30 사용자 지시)

**거래명세서가 있어야만 지결을 올릴 수 있다.** 예외는 하나 — 세금계산서에 **입고 일자별로 품명·수량·단가가 모두** 적혀 있으면 그 계산서가 명세서를 대체한다.

- 품목이 한 줄로 뭉뚱그려져 있거나(예: 「부각포장지」 한 줄) 수량·단가 칸이 비어 있으면 **대체 불가**
- 일자 구분 없이 월 합계만 있는 것도 대체 불가 — **입고 일자별**이어야 한다
- 대체 불가면 명세서를 받을 때까지 **작성완료를 누르지 않는다**
- **분할 결제(선금 50% → 잔금) 건**은 ① 계약(견적) 총액 ② 선금 계산서 ③ 잔금 계산서를 나란히 놓고 `선금 + 잔금 = 최종 총액`을 검산한다. 견적에 「실제 나오는 수량에 따라 금액 변동」 류의 단서가 있으면 **품목별 최종 생산수량이 적힌 거래명세서**가 있어야 잔금 금액을 확정할 수 있다 — 품목별 단가가 다르면 금액 하나로는 수량이 역산되지 않는다 (2026-10-30 태백비닐)

- **제때에서 운영하는 품목(제때 코드 CC…로 발주진행현황에 있는 품목)은 매입확정 기록까지 확인하고 올린다** (2026-11-04 사용자 지시 — 좋은에프앤비 11월 지결이 이 검증 없이 진행됨). 매입마감담당이 매일 아침 제때 매입확정분을 구글시트 「발주진행현황」(`N월_발주진행현황` 탭) **P 입고일자 · Q 입고수량**에 기록하므로, 지결 품목마다 코드(H)로 그 행을 찾아 **P·Q가 채워져 있는지 + 명세서 수량과 맞는지**(단위 환산 포함, 예: 참머리 40 BOX × 5두 = 200 EA, 곱창 48 PK × 1.5kg = 72kg) 대조한다. P·Q가 비어 있으면 = 제때 매입확정 전 → 작성하지 않고 「확인 필요(매입확정 전)」. 보고·승인 카드 check 칸에 「발주진행현황 Q 40 BOX = 명세서 200 EA」처럼 숫자를 같이 적는다. 시트는 읽기만
- 금액이 확정됐는데 명세서가 아직이면 **작성하지 않고 「작성 대기」로 등록**한다 (전에는 `증빙 미제출 사유: 댓글 첨부하겠습니다.` 로 올렸으나, 그건 **거래명세서는 있고 세금계산서만 없는** 경우에만 쓴다)
- 대기 목록: `state/pending_expense.json` — 거래처·고정양식·금액·이체요청일·지출내용·필요 증빙·파일명 매칭어(`match`)·등록일(`added`)

**감지 — `scripts/evidence_watch.py`** (고정 스크립트, 슬랙 봇 감시 목록 「증빙 도착 확인 10시·17시」가 월~금 10시대·17시대에 1회씩 호출 — 2026-11-05 작업 스케줄러 「계산서 수집 (월-금 10시·17시)」에서 옮김, 그 작업은 사용 안 함)

## 10. 보고·승인 규칙 — 「금액 대조 → 이미지 → 진행/거부」 (2026-10-30 사용자 지시)

**한 일을 보고할 때는 대조를 끝낸 뒤에 말한다.** 「계산서 받았어요」가 아니라 **「거래명세서 1,485,000 = 계산서 1,485,000 일치 확인」** 처럼 두 숫자를 같이 적는다.

- 대조 상대는 **거래명세서**가 1순위, 거래명세서가 없으면 지결 작성 금액(= 매입사마감 시트/발주진행현황 확정액)
- 두 문서를 **직접 열어 본 뒤에만** 「일치 확인」이라고 쓴다. 금액을 못 읽었으면 「미확인」, 숫자가 다르면 「불일치 — 확인 필요」로 적고 **첨부·작성을 진행하지 않는다**
- 대행사 계산서처럼 금액이 안 보이는 건(업체명만 파싱된 건)은 `scripts/agency_invoice.py`로 원본을 열어 금액을 읽고 나서 보고한다

**2026-11-02 사용자 지시로 변경** — **노션에 지결 카드가 이미 작성돼 있고 금액이 맞으면 승인 카드 없이 바로 댓글 첨부한다.** 대조(카드 금액 = 계산서 합계)는 그대로 먼저 하고, 불일치·카드 없음·어느 카드인지 모호하면 첨부하지 않고 「확인 필요」로 보고한다. 승인 카드는 **지결을 새로 작성(작성완료)하는 건**에만 올린다.
  - 근거 (2026-11-04 사용자 재확인): **노션 카드에 거래명세서가 첨부돼 지결이 이미 작성돼 있다면, 그 지결은 작성 때 매입확정 내역(발주진행현황 P·Q)까지 검토를 마친 건**이다. 그래서 계산서만 붙이는 일은 승인 없이 바로 업로드한다. 이 경우 발주진행현황 재대조도 하지 않는다(카드 금액 = 계산서 합계 대조만)

**승인 카드 (봇이 만든다)** — 응답 맨 끝에 건마다 한 줄:

```
APPROVAL {"id":"okfood10","title":"오케이식품 10월 마감정산","check":"거래명세서 1,485,000 = 계산서 1,485,000 일치 확인","summary":"이체요청일 10/30 · 블루트렌드","images":["C:\\Users\\BLUETREND\\Desktop\\지출결의 증빙 이미지\\오케이100.png"],"action":"노션 「확인용」 카드 댓글에 첨부"}
```

- `check` — 금액 대조 결과. 비어 있으면 카드에 「⚠️ 금액 대조 결과가 안 적혀 있어요」가 대신 뜬다(= 잘못 보고한 것)
- `images` — **계산서·증빙 PNG를 먼저**, BT FLOW 작성 화면 캡처를 뒤에. 사용자는 이 이미지만 보고 누른다. 경로의 `\`는 `\\` 또는 `/`
  - 작성 화면 캡처는 **크롬 탭을 닫기 전에** `save_to_disk`로 떠 둔다(탭을 닫은 뒤엔 못 뜬다). 못 떴으면 증빙 PNG만으로 카드를 올리고 `summary`에 「작성 화면 캡처 없음」이라고 적는다
- **새로 작성하는 건은 대조가 끝나면 예외 없이 카드로 올린다 — 본문에 글로 「승인해 주세요」라고 쓰지 않는다.** 증빙이 원본이 아니거나(카톡 썸네일 확대본 등) 입고 확정 전인 것은 카드를 막는 사유가 아니라 `summary`에 적을 특이사항이다. 카드를 안 올리는 경우는 **금액 대조 자체를 못 했을 때뿐**(그때는 「확인 필요」)
- 버튼 **「▶️ 진행 / 👀 직접검토 / ❌ 거부」** (`shared/slack_bot/bot.py` `CHOICE`)
  - 진행 → 같은 세션을 이어 그 건의 `action`만 실행 · 직접검토 → 손대지 않음 · 거부 → 이유를 받아 업무노트 제안
- 카드 기록은 `shared/slack_bot/state/approvals.json` (대조 결과까지 같이 남음)
