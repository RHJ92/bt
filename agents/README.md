# agents — 구매팀 업무 자동화 에이전트 거점

메일·카톡으로 들어오는 업무를 감지·분류해서 업무별 에이전트가 처리하고, 사람 판단이 필요한 건 개인 슬랙에서 승인받는 구조. 커리큘럼 2단계 「Slack 슈퍼팀」.

- 거점 신설: 2026-10-28. **이 폴더는 에이전트 전용 세션에서 작업한다**
- 테스트: 개인 슬랙 (회사 허락받음) → 검증 끝나면 회사 계정으로 같은 구조 그대로 이전
- 메일 수신: **이카운트 웹메일 IMAP 직접 읽기** (2026-10-29 변경). 웹메일 자동전달이 관리자 권한(Self-Customizing)이라 Gmail 경유 경로 폐기
- 첫 업무 2종: **발주 자동입력**(`order_intake/`), **지결 자동입력**(`expense_report/`)

## 폴더 구조

```
agents/
├─ README.md            ← 이 문서 (구조·공통 원칙·진행 현황)
├─ shared/              ← 업무 공용 부품
│  ├─ mail_intake/      ← 이카운트 IMAP 접속(읽기 전용)·폴더 조회, 메일 파싱 공용 함수
│  ├─ kakao_intake/     ← 카톡 수신 감지 (카톡 MCP 검토·감지 시험 결과)
│  ├─ slack_bot/        ← 개인 슬랙 봇 (Socket Mode). 업무별 채널·승인 버튼
│  └─ config/           ← 슬랙 토큰·채널 ID (깃 미추적). 메일 비밀번호는 여기 아님 → Windows 자격 증명 관리자
├─ order_intake/        ← 제때 발주 메일 → DAILY 발주진행현황 E·H·L 자동입력
│  ├─ README.md         ← 설계·판단 규칙표·진행 순서

│  └─ tests/fixtures/   ← 검증용 과거 발주 메일 샘플
└─ expense_report/      ← 지결 자동입력
   ├─ README.md         ← 슬랙 승인형 설계 원본 (2026-10-28 memo/에서 이동)

```

깃 미추적: `shared/config/`, 각 폴더의 `logs/`·`state/`, 원본 메일 `.eml` (루트 `.gitignore`)

## 공통 원칙

- **판단은 사람, 준비는 AI, 실행은 고정 스크립트.** 돈 나가는 동작(상신)·외부 발송(메일 답장)은 슬랙 승인 후 정해진 스크립트만 실행. AI가 스스로 누르지 않는다
- **정형 업무는 규칙으로.** AI(`claude -p`)는 처음 보는 형식·분류 안 되는 건에만
- **사람 손 없이 감지.** 사용자가 "저장"을 눌러야 하는 감지 방식 금지
- **타 부서 요청·협조가 필요한 설계 금지**
- 비밀번호 로그인을 자동화가 대신 하지 않는다 → 로그인 없는 경로(OAuth·API) 사용. **예외: 이카운트 메일 IMAP** — 웹 로그인 화면 조작이 아니라 메일 프로그램 계정 등록과 같은 방식. 비밀번호는 Windows 자격 증명 관리자(`ecount-imap`)에만, 메일함은 읽기 전용(2026-10-29)
  - **예외: 화면 API 로그인** — 공개 API가 없어 사용자가 승인한 곳만. 비밀번호는 사용자가 등록 스크립트로 자격 증명 관리자에 넣고, 고정 스크립트만 쓴다. **제때 ebiz**(`jette_daily/`, 재고·매출 조회) · **마켓봄 9517·3802·10509**(`inventory_sync/`, 2026-11-02 승인, 9517 문자·OTP 없음 확인) · 에이엠비 재고수불(`expense_report/scripts/wms_amb.py`, 조회)
- 계정 관리: 저장소 `계정보관/계정목록.xlsx`(깃 제외, 사용자 입력) → `계정반영.bat`(`shared/account_sync.py`)으로 자격 증명 관리자·config에 반영. 스크립트는 자격 증명 관리자만 읽고, 에이전트는 이 폴더를 열지 않는다
- 회사 시트 쓰기는 업무별로 허용 범위를 README에 명시 (예: 발주 = 발주진행현황 E·H·L만). 쓰기 전 `purchase_closing/sheet_snapshot.py`로 스냅샷
- 실행 기반: 회사 PC 작업 스케줄러 (참고 구현: `agent_livestock_products/automation/`)
- **백업·지난 결과는 `agents/_삭제대상/`에 모은다 (2026-11-05 사용자 「동작에 꼭 필요한 게 아니면 삭제 대상 폴더로 — 정리해 가면서 관리」).** 깃 미추적, 사용자가 직접 비움. 담당이 고치기 전 백업은 처음부터 `_삭제대상/문서백업/`·`시트백업/`에, 그 밖에 쌓이는 파일(봇 결과 3일·슬랙 첨부 7일·마켓봄 엑셀 3일·제때 미리보기 최근 3회·로그 30일 등)은 `shared/cleanup.py --move`가 `_삭제대상/YYMMDD/`로 옮김(봇이 월~금 08:00 조용히 실행, 실패만 #공통_작업완료)(원래 경로 유지 → 되돌리기 가능). 새 스크립트가 백업·임시 파일을 만들면 cleanup.py 규칙에도 한 줄 추가

**담당끼리 업무 넘기기 (2026-10-30)**: 담당이 다른 담당 범위가 필요하면 응답 끝에 `HANDOFF {"to","task","why"}` → 봇이 받는 담당 채널에 「📨 #A → #B 업무 요청」 글을 올리고 B가 처리 → 결과를 A의 원래 스레드에 「📬 #B 회신」으로 붙이고 A가 이어서 마무리. **넘기기는 사용자 지시에서 한 번만**(넘겨받은 일·회신 받은 일에서 또 넘기면 멈추고 담당 채널). 기록 `shared/slack_bot/state/handoffs.json`. 봇 재시작 중이던 넘기기는 회신이 안 붙을 수 있음 → 원래 스레드에 「이어서」.

**한 업무 = 한 창구 (2026-11-06, 루트 CLAUDE.md)**: 호정님은 한곳에만 말한다. 슬랙 담당 공통 지시(`bot.py` `SYSTEM`)에 반영 — 담당은 「다른 세션/채널에 가서 하세요」라고 안내하지 않는다. 다른 담당 실행이 필요하면 HANDOFF, VS Code 영역 세션 몫의 판단이 필요하면 그 스레드에서 호정님께 직접 묻고 진행. 돈 나가는 일·외부 발송만 승인 카드(예외).

**카톡 읽기 공용 도구 `shared/kakao_intake/kakao.py` (2026-11-06 재개, 읽기·저장만)**: 담당·세션 누구나 업체 단톡방을 캡처로 보고, 숫자가 필요할 때만 원본(파일·사진)을 저장해 다른 근거와 대조. 보내기 기능 없음. 사용법·시험 결과는 `shared/kakao_intake/README.md` §5. 담당 공통 지시(`bot.py` `SYSTEM`)에 반영.

**VS Code → 담당 위임 `shared/slack_bot/ask.py` (2026-11-06, 🧭 총괄 작성)**: VS Code 세션이 호정님 대신 슬랙 담당에게 일을 맡기고 결과를 받아 그 세션에서 이어서 처리하는 도구. 봇 「예약 작업」 대기열(`state/schedule.json`)에 지금 시각으로 넣음(`ask_id` 포함) → 봇이 최대 5분 안에 담당 채널에 **「📨 VS Code 위임」** 글(머리말 `[요청 ID] ○○ 세션이 호정님 대신 맡긴 일`)을 올리고 1회 작업으로 실행(일반 예약 작업은 「⏰ 예약 작업」) → ask.py가 `logs/bot.log` 시작·끝을 보고 `state/out/` 결과를 출력. 요청 기록 `state/ask_requests.json`.
