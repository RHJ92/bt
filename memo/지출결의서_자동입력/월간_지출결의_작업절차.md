# 월간 지출결의 작업 절차 (매입사 마감 → 지출결의서 작성)

새 세션에서 이 문서만 읽고 바로 이어받을 수 있게 쓴 작업 문서. 2026-10-16 사용자 설명 + 실물 화면 확인으로 작성.
BT FLOW 양식 입력 조작은 [BT_FLOW_작성절차.md](BT_FLOW_작성절차.md)에 따로 있다. 이 문서는 **그 앞 단계(금액을 어떻게 확정하는가)**가 핵심이다.

## 한눈에 보는 흐름

1. **결제일 확인** — 구글 캘린더에서 이번 회차 「지출결의」 날짜를 본다
2. **대상 추리기** — 매입사마감 시트에서 그 결제일에 해당하는 매입사를 고른다
3. **정산금 확정** — 발주진행현황·매입사 명세서·제때 입고내역을 대조해 「계산서 금액」을 확정한다
4. **증빙 저장** — 바탕화면 `지출 증빙 이미지`에 `매입사명+월` 파일명으로 저장
5. **지출결의서 작성** — BT FLOW → 탈리 폼 (작성 절차는 별도 문서)
6. **등록 확인** — 노션 「법인 지출통합결의서 확인용」에서 올라갔는지 확인

## 3. 정산금(계산서 금액) 확정 — 두 갈래

### ① 발주진행현황과 그대로 맞는 매입사

`N월_발주진행현황` 시트의 **입고확인·매입가 블록(P~V열)**과 매입사마감 집계가 일치한다. 그대로 계산서 금액에 넣으면 된다.

발주진행현황 열 구성(2026-10 기준): `I 제품명 / J 출고단위 / K 입수량 / L 요청수량 / M 박스환산 / N 비고(LOT·이력) / **P 입고일자 · Q 입고수량** / R 과세여부 / **S~V BT 구매단가(bt단가·bt매입단가·bt부가세·bt매입가)** / W~Z 제때 적용단가(jt단가·jt매입단가·jt부가세·jt매입가)`

### ② 날짜가 어긋나 매칭이 안 되는 매입사 (축산·수산 계열)

**매입사의 매입일자와 제때 입고일자가 달라** 자동 집계와 매입사 청구가 맞지 않는다. 이 경우 아래 셋을 **다각도로 대조**해 실제 정산금을 산출한다.

1. **매입사 명세서** (업체가 보낸 원본)
2. **축산_claude 스프레드** (축산품 구매·가공·입고 이력)
3. **제때 입고내역** (발주진행현황 입고확인)

→ 산출한 금액을 매입사마감 **「계산서 금액」**에 입력하고, 차이가 왜 났는지는 비고에 남긴다.

**선우프레시가 대표 사례** (2026-10-29 사용자 설명) — 시트 BT매입가와 업체 원장이 크게 달라도 정상일 수 있다.
- **아롱사태·스지**만 제때로 바로 입고된다
- **BBQ·삼겹양지**는 **신우미트로 들어가 가공**된 뒤 **뼈갈비절단·우삼겹슬라이스**로 제때에 입고된다 → 제때 입고내역에는 원물이 아니라 가공품으로 잡힌다
- **아롱사태도 창고에 보관했다가** 나중에 제때로 입고되면, 매입사 매입일과 제때 입고일의 월이 달라져 BT 구매가 집계와 맞지 않는다
- → 선우프레시는 **업체 거래처원장(월 발생분)을 정산금 기준**으로 삼는다. 원장에 중량 정산(기존 청구 취소 후 실중량으로 다시 청구) 행이 섞여 있으니 순액으로 본다

**창고 보관 원물의 실계근 차이 정산** (2026-10-29 사용자 설명)
- 창고 출고 시 실계근(창고 WMS `nwill.net` 출고 계근 조회)이 매입 중량과 다르면 차이만큼 정산한다. 시트는 「축산품창고」 출고량을 실계근으로 고치면 미출고재고에 차이가 남는다
- **선우프레시**: 업체가 마감원장에 알아서 반영해 준다 (예: 10/7 아롱사태 중량 정산 −288,721)
- **캐틀팜·케이팩토리**: 반영해 주지 않으므로 **실계근 차이 명세서 발행을 따로 요청**한다 → 매입 초과분은 반환 요청, 부족분은 추가 정산. **두 회사는 자회사 관계로 담당자가 1명이라 요청은 한 건으로 묶어 보내되, 명세서는 법인별로 받는다**
- 2026-10 사례: BBQ백립 803042103317(7/15 매입, 12,000원/kg) 10/12 신우미트 출고 — 캐틀팜 430박스 11,089.70 → 실계근 11,009.38(**−80.32kg, 963,840원 반환 요청**) / 케이팩토리 150박스 3,868.50 → 3,870.97(**+2.47kg, 29,640원 추가 정산**) — 10/29 요청 → **당일 수정 명세서 수신**(캐틀팜 10/14자 전표54 −963,840 `캐틀팜10-1.png` / 케이팩토리 10/29자 전표15 +29,640 `케이팩10.png`). 창고 탭 14·15행은 「출고일(2)·출고량(2)」에 명세서 날짜·차이 중량을 넣어 미출고재고 0으로 정리(실계근 차이 조정용으로 이 칸을 쓴다)

**주의** — 매입사 표기가 시트마다 다른 곳이 있다 (예: `IC푸드`=아이씨푸드, `푸미푸드`=푸미식품, `평중-담터`=평중(담터), `삼정식품`=삼정식품(좋은에프앤비)). 이름이 안 맞는다고 누락으로 보지 말 것. 대조 이력은 [README.md](README.md) 하단에 정리돼 있다.

## 4. 증빙 저장

- 위치: **바탕화면 `지출 증빙 이미지` 폴더** (`C:\Users\BLUETREND\Desktop\지출 증빙 이미지`)
- 파일명: **매입사명 + 해당월** 조합. 특이사항이 없으면 이 규칙대로만 저장한다
- 관찰된 규칙: `명화10.png`(10월 거래명세서) / `명화100.png`(10월 세금계산서 — 끝에 0 하나 더) / 같은 달 2건째는 `-1`(`명화10-1.pdf`·`명화100-1.png`)
- 다른 업체 예: `캐틀팜10`·`캐틀팜100`, `케이팩108`·`케이팩1080`, `swc09`·`swc090`

## 5. 예외 — 매입사마감 리스트에 없는 건

아래는 **발주진행현황에서 집계되지 않으므로 매입사마감 시트에 애초에 안 잡힌다.** 건별로 따로 지출결의서를 쓴다.

- **일회성 매입** (예: 2026-10 명화주방 티타늄 국그릇·김치찜접시 선결제)
- **제때에 입고하지 않는 건** (창고보관료·운송비·선결제 업체 등)

→ 금액은 매입사 명세서·세금계산서로 직접 확정한다.

- **영영상점(블루푸드랩·영영키친 법인) 관련 매입**(예: 더푸른별)도 매입사마감 시트에 행이 없고, **시트에 입력하지 않는다** (2026-10-29 사용자 확정)

## 5-3. 반환(입금 예정) 건 — 마이너스 지출결의

업체에서 돈을 돌려받을 때도 **금액을 마이너스로 한 지출결의서**를 쓴다 (2026-10-29 사용자 지시, 캐틀팜 실계근 차이 −963,840).
- BT FLOW 화면의 금액 칸은 마이너스를 지워 버린다 → **비워 두고 탈리 폼 열기 후 탈리 금액 칸에 `-963840` 직접 입력** (탈리는 −963,840으로 받음)
- 지출내용·목적은 반환 건에 맞게 고친다 (예: `10월 BBQ백립 실계근 차이 반환` / `축산품(BBQ백립) 실계근 차이 정산(입금 예정)`)
- 이체요청일은 가장 가까운 결제 회차

## 5-2. 세금계산서 회신 → 노션 카드 댓글 첨부

계산서 없이 `댓글 첨부하겠습니다.`로 올린 지결은 **결제일 전까지** 계산서를 노션 카드 댓글로 붙인다.

1. 이카운트 메일 검색 `국세청` → 「주식회사 블루트렌드 (업체->주식회사 블루트렌드)」 메일
2. 첨부 `NTS_eTaxInvoice.html`은 **보안메일 — 비밀번호(사업자번호) 입력은 사용자가 직접**. 사용자가 열어 캡처를 채팅에 붙여 줌 → `업체100.png`로 증빙 폴더 저장, 금액 대조
3. 노션 「확인용」 → Master DB 검색(돋보기)에 업체명 → 해당 카드 URL로 페이지 열기
4. Comments의 Attach file은 OS 파일창이 떠서 직접 못 누름 → JS로 `HTMLInputElement.prototype.click`을 가로채 file input을 DOM에 붙인 뒤 `file_upload`로 올리고 전송(↑) 클릭 (2026-10-29 에치알푸드로 성공)
