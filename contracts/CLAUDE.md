# contracts — 계약서 관리

매입처·생산처·물류사와의 물품공급계약, 부속 합의서, 체결 전 협의(수정 요청) 서면을 관리하는 거점. **계약 1건 = 폴더 1개**로 초안부터 체결본까지 한곳에 모은다.

## 폴더 구조

```
contracts/
├─ CLAUDE.md                     ← 이 문서 (절차·체크리스트·문안·진행 현황)
└─ 업체_계약명/                   ← 계약 1건 = 폴더 1개 (예: 카우스토리_철산장육수)
   ├─ README.md                  ← 경과·버전별 수정 내역·최종 조건·체결 정보
   ├─ 업체_물품공급계약서.docx     ← ① 당사 초안
   ├─ …_상대 수정본.docx          ← ② 상대 회신본 (받은 그대로, 수정 금지)
   ├─ …_YYMMDD.docx              ← ③ 최종본 (상대 수정본 + 당사 기재분)
   ├─ …_체결본.pdf                ← ④ 전자서명 완료본 (싸인오케이에서 다운로드)
   └─ YYMMDD_업체_주제.md          ← (필요 시) 위험 조항 검토·수정 요청 서면
```

- 업체와의 실무 협의(원가·수율·견적)는 각 거점 폴더(bidding 등)에 두고, **계약서 파일만** 여기로 모은다. 거점 README에는 이 폴더 링크만 남긴다
- 파일 수정은 원본을 두고 `_YYMMDD` 붙인 새 파일로 (같은 날 재수정은 덮어씀)
- 상대가 보낸 파일은 이름에 `_상대명 수정본`을 붙여 받은 그대로 보관

## 계약 진행 절차

| 단계 | 할 일 | 산출물 |
|---|---|---|
| 1. 초안 작성 | 당사 표준 물품공급계약서 기반으로 당사자·품목 반영. 단가표·계약기간·상대 사업자정보는 공란으로 두고 상대에게 기재 요청 | ① 초안 docx |
| 2. 초안 발송 | 메일 송부(아래 문안) + 카톡으로 메일 보냈다고 알림 | — |
| 3. 상대 수정본 검토 | 원본 ↔ 수정본 **전문 비교**(아래 방법) → 바뀐 곳을 조항 추가 / 공란 기재 / 문구 변경 / 변경 없음으로 나눠 팀장 보고. 불리한 조항이 있으면 `/contract-review`로 수정 요청 서면 | 비교 정리(README에 기록) |
| 4. 최종본 확정 | 상대 수정본 위에 당사 기재분(단가표 등)만 추가 → 최종본 메일 송부. **첨부 파일명 재확인**(초안 오첨부 사례 있음) | ③ 최종본 docx |
| 5. 전자서명 | 싸인오케이로 서명 요청(아래 절차). 당사 서명 먼저 → 상대에게 카톡 안내 | — |
| 6. 체결·보관 | 서명 완료 알림 오면 싸인오케이 내 문서함 → 행 「⋯」 → 다운로드 → 폴더에 `…_체결본.pdf`로 저장(서명 페이지 인감 확인), README·진행 현황 갱신 → 회사 노션 「BT 계약서 DB(구매공급관리팀)」에 행 추가(계약법인·계약 부서·계약 상대방·계약유형·상황 확정·계약일·계약서 파일 첨부) | ④ 체결본 pdf |

**수정본 비교 방법:** Git Bash에서 `pandoc 원본.docx -t plain --wrap=none` 으로 두 파일을 텍스트로 뽑아 `diff`. 서명란 표·별첨 표까지 비교된다. 상대가 변경 추적 없이 고쳐 보내는 경우가 많아 눈으로 훑지 말고 반드시 전문 비교.

## 발송 전 체크리스트

- [ ] 상대 상호·대표자명 — 통화·명함과 대조 (카우스토리 초안에서 "김형식 ↔ 김현식" 오기 있었음)
- [ ] 사업자등록번호·주소 — 당사(구매자)는 법인별로 정확히 (철산장 = ㈜철산장에프앤비 886-88-02905)
- [ ] 계약기간·계약일자 기재, 자동연장 조항 확인
- [ ] 별첨 단가표 — 품목명은 사업부(가맹본부) 확정명과 일치, 단가 VAT 별도/포함 병기, 미확정 품목은 공란 + "추후 협의"
- [ ] 첨부 파일이 **최종 버전**인지 파일명·수정 시각으로 확인

## 전자서명 — 싸인오케이 (https://doc.signok.com/okdj/dashboard.sg)

연 360건 요금제(2026-12-19까지), 발송 1건당 계약건수 1건 차감.

1. **계약 시작하기** → 처음이면 「휴대폰 본인인증」(연 1회, 사용자 직접 — Claude 대행 불가)
2. **문서 선택**: 직접 파일 업로드 (docx·hwp·pdf 가능, 10MB 이하) → 최종본 첨부
3. **서명자 정보 입력**: 비대면 서명 / 순서대로 한 명씩 서명
   - 첫 번째 = 당사 측 서명자(구매자 법인 인감을 찍을 사람), 두 번째 = 상대 업체
   - 이름 + 이메일(또는 휴대폰)
4. **서명 영역 지정**: 왼쪽에서 서명자 선택 → 「서명」 클릭 → 문서의 「(인)」 위치 클릭
   - 기본 크기 50×50은 윗줄 글자를 덮음 → **모서리를 끌어 43×44 정도로 줄이고 「(인)」 위에 겹치게** 이동 (오른쪽 패널의 숫자 입력은 화면에 반영 안 됨)
   - 서명자별 색: 1번 빨강, 2번 파랑
5. 다음 단계 → 「저장하시겠습니까?」 저장 → **설정 및 요청**: 문서 제목(파일명 기본), 서명 기간 14일 기본
6. **서명 요청** → 확인창(서명자·차감 건수) → 확인 → 「이어서 서명하시겠습니까?」 → 당사 서명자가 직접 서명(Claude는 닫기)
7. 순차 서명이라 **당사 서명이 끝나야 상대에게 요청 메일이 간다** → 서명 후 상대에게 카톡 안내

## 위험 조항 검토 원칙 (상대가 조항을 고쳐 왔거나 상대 양식으로 받을 때)

상세 절차는 스킬 `/contract-review`.

- 우리에게 위험이 몰리는 조항부터 — 재고 인수 책임, 자율 매입 권한, 손해배상·지연이자, 해지 사유, 품질·클레임 책임, 단가 조정
- 조항 전부를 수정 요구하지 않는다. **실제로 터질 수 있는 것 1~2개만** 서면으로
- 요청 문구는 계약서 문체 그대로(~한다), 반영 방식은 3안(본문 항 추가 / 별도 합의서 / 메일 합의)
- 외부 문구에는 책임이 생기는 단정·약속·비교·전례 언급을 넣지 않는다
